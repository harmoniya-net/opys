# CLI

Три команди. Кожна робить трохи більше, ніж попередня.

| Команда        | Що робить                                   |
| -------------- | ------------------------------------------- |
| `opys build`   | Запускає вашу конфігурацію і записує бандл. |
| `opys install` | Завантажує та розпаковує все. Без гри.      |
| `opys launch`  | Встановлює відсутнє, потім запускає гру.    |

```sh
npm install -g @opys/cli
```

## Щоденна робота

```sh
opys launch            # спробувати збірку, над якою ви працюєте
opys build             # записати бандл для поширення
opys launch game.opys --var root=/tmp/test …   # перевірити його як гравець
```

## Конфігурація або бандл

`install` і `launch` приймають будь-що з двох.

**Без аргумента:** вони читають `opys.config.mjs`, збирають його в
тимчасовий бандл і застосовують ваш `run`. Це для вас, поки ви робите
збірку.

**Шлях до бандла:** вони використовують цей файл як є. Конфігурація не
читається, тож немає `run`, а значення гравця приходять з `--var`. Так
робить гравець.

```sh
opys launch game.opys --var root=/path/to/install --var username=Player \
  --var uuid=00000000-0000-0000-0000-000000000001 --var token=0
```

## Прапорці

| Прапорець         | Команди             | Що робить                                             |
| ----------------- | ------------------- | ----------------------------------------------------- |
| `-i`, `--input`   | усі                 | Файл конфігурації. Типово `opys.config.mjs`.          |
| `-o`, `--output`  | `build`             | Бандл для запису. Перевизначає `output` конфігурації. |
| `--mode <name>`   | усі                 | Передається конфігурації як `mode`.                   |
| `--var key=value` | `install`, `launch` | Задає змінну. Можна повторювати.                      |
| `--feature a,b`   | `install`, `launch` | Вмикає прапорець, наприклад `java_console`.           |
| `--log-level <l>` | усі                 | `silent`, `error`, `warn`, `info`, `debug`.           |
| `-h`, `--help`    |                     | Друкує підказку.                                      |

Варто знати:

- `--var` виграє в тієї самої змінної з `run`.
- Відносні `-o` або `output` відносні до файла конфігурації.
- Без названого виходу взагалі `build` друкує маніфест як JSON. Добре
  для читання та порівняння, не для встановлення.

## Коли використовувати `install`

Forge і NeoForge завершують своє налаштування на комп'ютері гравця,
зазвичай під час першого запуску. `opys install` робить це наперед.

Використовуйте його, щоб підготувати встановлення, або в скрипті, який
не має запускати гру.

## Коди виходу

| Код | Значення                                                |
| --- | ------------------------------------------------------- |
| 0   | Успіх.                                                  |
| 1   | Помилка в команді чи конфігурації або невдале збирання. |
| 2   | Не вдалося завантаження.                                |
| 3   | Файл не збігся зі своїм хешем.                          |
| 4   | Не вдалося розпакувати архів.                           |
| 5   | Гра стартувала, потім вийшла з власною помилкою.        |

Що робити з кожним: [усунення проблем](/uk/reference/troubleshooting).
