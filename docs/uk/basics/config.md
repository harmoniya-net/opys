# Конфігурація

`opys.config.mjs` це звичайний файл JavaScript. Він описує одну збірку.

## Найменша конфігурація

<<< @/examples/basics-intro/opys.config.mjs

Чотири частини, завжди ті самі:

| Частина    | Що означає                       |
| ---------- | -------------------------------- |
| `output`   | Куди `opys build` записує бандл? |
| `plugins`  | З чого складається збірка?       |
| `manifest` | Як запускається гра?             |
| `run`      | Що знає лише комп'ютер гравця?   |

`defineConfig` нічого не змінює. Він потрібен, щоб ваш редактор
перевіряв конфігурацію, поки ви пишете.

Решта цієї сторінки проходить по кожній можливості: що вона робить,
коли вона вам потрібна і чому вона влаштована саме так.

## Плагіни

<!-- prettier-ignore -->
```js
plugins: [
  forge({ version: '1.20.1' }),
  java({ version: '17' }),
],
```

Плагін додає частину збірки: файли, змінні, частини командного рядка.
Список плаский, і кожен плагін приймає один об'єкт з параметрами.

**Чому плагіни?** Справжнє встановлення це тисячі файлів. Ніхто не має
писати цей список вручну, і кожен плагін добре знає свою частину.

**Коли два плагіни сперечаються**, виграє пізніший у списку. Для
змінних збирання також друкує попередження, бо зазвичай це випадковість.

Які плагіни існують і що кожен з них додає: [Плагіни](/uk/plugins/).

## Рядок запуску

```js
manifest: {
  command: '@forge.command',
  args: ['@forge.jvmArgs', '-Xmx4G', '@forge.mainClass', '@forge.gameArgs'],
  workdir: '${game_directory}',
},
```

Рядок, що починається з `@`, це **посилання**: `'@forge.jvmArgs'`
стає аргументами JVM, які обчислив плагін `forge`. Все інше
передається як написано.

**Коли ви його чіпаєте:** щоб додати власні прапорці (`-Xmx4G`) або
поставити аргументи іншого плагіна в певне місце, наприклад агента
авторизації, який має йти першим.

**Чому ви пишете його самі:** порядок аргументів важливий для Java, і
лише ви знаєте, що потрібно вашій збірці. Тому opys нічого не вгадує.
Він дає вам частини, а ви їх розставляєте.

**Одруки перехоплюються.** Посилання, що не називає нічого, зупиняє
збирання і перелічує те, що існує. Ваш редактор підсвітить його ще
раніше.

::: details Два невеликі правила

- Для аргумента, який справді починається з `@`, пишіть
  `'\\@args.txt'`.
- Беріть `command` із завантажувача (`'@forge.command'`), а не з Java
  напряму. Тоді ваша конфігурація працюватиме далі, якщо завантажувачу
  колись знадобиться запускатися інакше.

:::

## Змінні

```js
workdir: '${game_directory}',
```

`${name}` це заповнювач. Він заповнюється на комп'ютері гравця, коли
гра встановлюється та запускається.

**Чому:** бандл це той самий файл для кожного гравця, але кожен
гравець встановлює в інше місце. Тому шляхи пишуться відносно
`${root}`, а комп'ютер гравця каже, чому дорівнює `root`.

**Обережно:** ім'я, яке ніхто не визначив, лишається як написано,
мовчки. Якщо гра показує гравця на ім'я `${username}`, сталося саме
це.

Усі імена: [Змінні](/uk/plugins/minecraft#змінні).

## run

```js
run: (manifest) => ({
  vars: {
    ...manifest.vars,
    root: userDataDir('my-pack'),
    username: 'Player',
    uuid: '00000000-0000-0000-0000-000000000001',
    token: '0',
  },
}),
```

`run` викликається на комп'ютері запуску щоразу, коли гра стартує. Він
повертає частини маніфесту, які треба замінити.

**Коли він потрібен:** завжди, для `opys launch`. Він дає теку
встановлення та гравця.

**Чому він окремо від `manifest`:** все під `manifest` запечене в
бандл і спільне для кожного гравця. Ваша домашня тека і ваш токен там
бути не повинні. `run` ніколи не запечений.

::: warning Класична помилка
`userDataDir()` у `manifest.vars` запече _вашу_ домашню теку в бандл.
Тоді збірка працює у вас і ні в кого більше. Тримайте його в `run`.
:::

Залишайте `...manifest.vars`. Кожне поле, яке ви повертаєте, замінює
старе цілком, тож без цього поширення змінні плагінів губляться.

Бандл не містить `run`. Той, хто запускає бандл, передає ті самі
значення через `--var` або зі свого лаунчера.

## Власні змінні та середовище

```js
manifest: {
  vars: { pack_version: '1.4.0' },
  envs: { PACK_VERSION: '${pack_version}' },
},
```

`vars` додає змінні. `envs` задає змінні середовища для гри.

**Коли:** стала, яку ви хочете в кількох місцях, або значення, яке мод
читає із середовища.

**Також для перевизначень.** `manifest.vars` виграє в будь-якого
плагіна, без попередження. Це місце, де вирішується суперечка, коли
змінну задають два плагіни.

Лише сталі. Вони запечені в бандл, тож ніяких шляхів і ніяких
секретів.

## Параметри

Що гравець може змінити перед запуском: пам'ять, роздільну здатність,
перемикач.

<!-- prettier-ignore -->
```js
import { defineConfig, options } from '@opys/dev';

export default defineConfig({
  // ...
  options: options()
    .slider('xmx', { min: 1024, max: 16384, step: 512, default: 4096 })
      .title('RAM')
      .unit('MB')
    .select('preset', { low: 'Low', high: 'High' })
      .title('Graphics')
      .default('high')
    .feature('custom_java', (o) => o
      .directory('java_home')
        .title('Java folder'))
      .title('Custom Java'),
});
```

Вид додає налаштування. Кроки після нього належать цьому
налаштуванню, до наступного виду.

| Вид                        | Задає     | У                       | Його кроки               |
| -------------------------- | --------- | ----------------------- | ------------------------ |
| `.slider(name, range)`     | змінну    | Число в діапазоні.      | `unit`                   |
| `.select(name, choices)`   | змінну    | Один із `choices`.      | `default`                |
| `.text(name)`              | змінну    | Рядок тексту.           | `placeholder`, `default` |
| `.file(name)`              | змінну    | Шлях файла.             |                          |
| `.directory(name)`         | змінну    | Шлях теки.              |                          |
| `.feature(name, options?)` | прапорець | Увімкнено або вимкнено. | `default`, `options`     |

Кожен вид також має `title` і `subtitle`.

- Ім'я це змінна або прапорець, які ваш маніфест уже використовує:
  `${xmx}` в аргументі, `allow.features.custom_java` у правилі.
- **Кожне налаштування потребує `title`.** `opys build` назве те, в
  якого його немає.
- Вибір починається з першого варіанта, якщо `default` не каже інакше.
- Прапорець вимкнений, якщо немає `.default(true)`.
- Налаштування під прапорцем мають значення, лише поки він увімкнений.
- `opys build` відхиляє ім'я, використане двічі, і типову
  повзунка поза його діапазоном.

::: warning
Варіанти показані в порядку написання, крім значень, схожих на цілі
числа. JavaScript перелічує такі першими, у числовому порядку:
`{ b: 'B', 2: 'Two', 1: 'One' }` показаний як One, Two, B.
:::

**По одному.** Кожен вид це також функція, для списку або для
прапорця, що читається згори вниз:

```js
import { directory, feature, slider } from '@opys/dev';

options: [
  slider('xmx', { min: 1024, max: 16384, step: 512, default: 4096 })
    .title('RAM')
    .unit('MB'),
  feature('custom_java')
    .title('Custom Java')
    .options(directory('java_home').title('Java folder')),
],
```

**Це опис, а не значення.** Налаштування йдуть у бандл, щоб лаунчер міг
намалювати екран налаштувань. Лаунчер передає вибране гравцем як `vars`
і `features`. `opys launch` їх не читає: використовуйте `--var` і
`--feature`.

## cleanup

```js
manifest: {
  cleanup: [{ includes: ['${game_directory}/mods/*.jar'] }],
},
```

Видаляє файли після встановлення.

**Коли:** ви прибрали мод зі збірки. Без `cleanup` гравці, які його
вже мають, збережуть jar назавжди, бо opys лише додає та оновлює.

**Чому це безпечно:** файл, який встановлює ваша збірка, ніколи не
видаляється, що б не казало правило. Тож правило вище означає «кожен
jar у `mods`, який _не_ є частиною цієї збірки».

```js
cleanup: [
  { includes: ['${game_directory}/config/**'], excludes: ['**/options.txt'] },
],
```

`excludes` щадить файли. `*` лишається всередині однієї теки, `**`
переходить через теки.

::: warning Тримайте правила вузькими
Правило, що збігається зі збереженнями гравця, видаляє його
збереження. opys відхиляє очевидно небезпечні (відносний шлях, `..`,
порожня змінна), але він не може знати, що важливе для гравця.
:::

## Налаштування плагіна

```js
modrinth({ versions, to })
  .exclude('**/*-sources.jar')
  .addRule('**/sodium-*.jar', 'disallow.os.osx'),
```

Кожен плагін можна налаштувати заднім числом.

**Коли:** плагін майже правильний. Один файл, якого ви не хочете, один
мод, що ламається на macOS, одне завантаження, яке ви хочете з
власного дзеркала.

| Метод                        | Що робить                         |
| ---------------------------- | --------------------------------- |
| `.exclude(match)`            | Відкидає файли, що збігаються.    |
| `.addRule(match, rule)`      | Обмежує їх платформою.            |
| `.updateFirst(match, patch)` | Змінює поля першого збігу.        |
| `.updateMany(match, patch)`  | Змінює поля кожного збігу.        |
| `.removeIntegrity(match)`    | Встановлює їх без перевірки хешу. |

`match` це глоб над шляхами файлів або функція. Починайте глоб з
`**/`: він порівнюється зі шляхом до заповнення змінних.

## Той самий плагін двічі

```js
modrinth({ versions: mods, to: intoMods }),
modrinth({ versions: packs, to: intoResourcePacks }).as('resourcepacks'),
```

**Коли:** один плагін, два призначення.

**Чому `.as()`:** посилання йдуть за ім'ям плагіна, тож два плагіни не
можуть ділити одне. `.as()` дає другому власне.

## Розробка та випуск з однієї конфігурації

```js
export default defineConfig(({ mode }) => {
  const dev = mode === 'dev';
  return {
    output: dev ? 'pack-dev.opys' : 'pack.opys',
    // ...
  };
});
```

```sh
opys build --mode dev
```

**Коли:** тестове збирання з зайвими модами, меншою пам'яттю або іншою
текою.

Без `--mode` значення `mode` це ім'я команди: `build`, `install` або
`launch`. Функція може бути `async`.

## Один файл вручну

```js
manifest: {
  artifacts: [
    {
      path: '${game_directory}/server-icon.png',
      source: { url: 'https://example.com/icon.png' },
      integrity: { sha256: '…' },
    },
  ],
},
```

**Коли:** рідко. [`links`](/uk/plugins/links) робить те саме і знаходить
хеш за вас. Це запасний вихід.
