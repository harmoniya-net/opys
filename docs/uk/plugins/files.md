# files

`files()` бере каталог на вашій машині збирання і створює артефакт для кожного файлу в ньому. Використовуйте його для того, що маєте на диску: приватного мода, згенерованої вами конфігурації, папки серверних налаштувань. Він походить з `@opys/dev`.

Типово файли везуться всередині бандла, тож нічого не треба хостити. Дайте йому `url`, і бандл натомість вказуватиме на копії, які хостите ви.

## Сигнатура {#signature}

```ts
function files(options: FilesOptions): ChainablePlugin;

type FilesOptions = EmbeddedFiles | PublishedFiles;

type FileTemplate = string | ((file: LocalFile) => string);

interface LocalFile {
  readonly rel: string; // шлях відносно `from`, з роздільниками `/`
  readonly dir: string; // частина `rel` з каталогом; '' на верхньому рівні
  readonly filename: string; // останній сегмент шляху
  readonly abs: string; // абсолютний шлях на машині збирання
  readonly size: number; // розмір на диску, в байтах
}
```

`EmbeddedFiles` це форма без `url`. `PublishedFiles` це форма з ним. Ці дві розрізняються за тим, яке поле ви даєте, а `hash` дозволений лише з `url`.

## Параметри {#options}

| Назва  | Тип                  | Типово   | Значення                                                                                                                            |
| ------ | -------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `from` | `string`             | required | Каталог, звідки беруться файли. Відносний шлях визначається від каталогу файлу конфігурації. Абсолютний шлях використовується як є. |
| `to`   | `FileTemplate`       | `${rel}` | Куди встановлюється кожен файл. Шаблонний рядок або функція від файлу.                                                              |
| `url`  | `FileTemplate`       | none     | Де хоститься копія кожного файлу. Якщо ви його даєте, на файли не везуться, а на них вказують.                                      |
| `hash` | `'sha1' \| 'sha256'` | `'sha1'` | Геш, за яким фіксується кожен файл, на який вказують. Лише з `url`.                                                                 |

Шаблонний рядок може використовувати три заповнювачі, які заповнюються для кожного файлу:

| Заповнювач    | Значення                                                            |
| ------------- | ------------------------------------------------------------------- |
| `${rel}`      | Шлях відносно `from`. Типове значення для `to`.                     |
| `${dir}`      | Частина `${rel}` з каталогом. Порожня для файлу на верхньому рівні. |
| `${filename}` | Останній сегмент шляху.                                             |

Будь-який інший `${name}` лишається як є, щоб заповнитися, коли гра встановиться. Тож `${game_directory}` і `${root}` працюють у `to` та `url`.

Функція отримує цілий `LocalFile`: `rel`, `dir` і `filename`, які є значеннями заповнювачів, а також `abs` і `size`. Лише форма з функцією отримує `abs`, тож форма з шаблоном не може використовувати шлях машини збирання.

## Поведінка {#behaviour}

**Везеться.** Без `url` кожен файл стає блобом. Назва блоба це sha256 його вмісту, а байти записуються до бандла під час `opys build`. Артефакт називає блоб і його розмір і не має власного гешу, бо назва і є гешем. `opys launch` читає байти звідти, де вони лежать на диску, тож нічого попередньо не копіюється.

**На нього вказують.** З `url` кожен артефакт отримує цю адресу як джерело, а також розмір і геш файлу. Файл гешується під час збирання, за sha1, якщо ви не задали `hash`, тож змінений файл має новий геш. opys нічого не завантажує на сервер. Ви кладете копії за названими вами адресами.

**Кожен файл під `from`.** Обхід рекурсивний і бере лише звичайні файли. За символічним лінком не йдуть, тож лінк за межі каталогу не може затягнути решту диска. Результат сортується за `rel`, тож дві збирання того самого дерева дають той самий маніфест. Порожній каталог не дає ні артефактів, ні помилки.

**Розміщення.** `to` вирішує, куди потрапляє кожен файл, і обчислюється для кожного файлу. Файл на верхньому рівні має порожній `${dir}`, тож `${dir}/${filename}` починається зі слеша. Використовуйте `${rel}` для шляху, який не залежить від глибини.

::: warning
Без `to` шлях артефакту це його голий відносний шлях, наприклад `settings.txt`, без жодної змінної попереду. Дайте `to` змінну, таку як `${game_directory}`, щоб файл потрапив туди, де його читає гра.
:::

**Помилки.** Відсутній `from` або `from`, який не є каталогом, каталог, який не читається, або файл, який не відкривається чи не читається під час гешування, зупиняє збирання. Помилка називає шлях.

**Ланцюжок.** `files()` повертає плагін, тож ланцюжкові методи працюють з ним. `.exclude(...)` відкидає артефакти, які збігаються. Решту див. у [`@opys/dev`](./dev).

## Приклад {#example}

Цей пак везе папку конфігів у бандлі. Папка це `config/` поруч із файлом конфігурації, вона тримає два текстові файли, один з них у підпапці:

```
config/
  settings.txt
  extra/
    tuning.txt
```

<<< @/examples/plugin-files-files/opys.config.mjs

Шаблон `to` зберігає структуру папки: `extra/tuning.txt` встановлюється до `${game_directory}/config/extra/tuning.txt`. Збирання записує ці два файли до бандла як блоби, і бандл не має URL для жодного з них.

Зберіть його командою:

```sh
opys build
```

Папка модів, на яку вказують, виглядає інакше, бо їй потрібен URL, який хостите ви. Ця фіксується за SHA-256 і використовує функцію для `to`:

```js
files({
  from: 'mods',
  to: (file) => `\${game_directory}/mods/${file.filename}`,
  url: 'https://cdn.example.com/my-pack/mods/${rel}',
  hash: 'sha256',
}),
```

`cdn.example.com` це заглушка. Шаблон `url` обчислюється так само, як `to`. Завантажте кожен файл за адресою, яку він дає, перш ніж гравці встановлять пак.

## Коли використовувати `links` натомість {#when-to-use-links-instead}

Використовуйте [`links`](./link), коли файл уже опубліковано, на GitHub, Modrinth, CurseForge чи за будь-якою іншою адресою, і ви маєте його URL. `links` бере геш у видавця або обчислює його один раз. Використовуйте `files`, коли файл існує лише на вашому диску. Про те, як моди та інші файли поєднуються, читайте у [Моди та файли](/uk/guide/mods).
