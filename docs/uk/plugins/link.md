# links

`links()` бере URL, які ви вже маєте, наприклад мод на Modrinth або файл релізу на GitHub, і перетворює кожен на фіксований файл у вашому маніфесті. Ви вставляєте лінк. opys визначає розмір і геш файлу під час збирання, тож інсталятору ніколи нічого не треба шукати. Він походить з `@opys/link` і реекспортується через `@opys/minecraft`.

Використовуйте його для файлів, які публікує хтось інший. Для файлу на власному диску використовуйте [`files`](./files).

## Сигнатура {#signature}

```ts
function links(options: LinksPluginOptions): ChainablePlugin;

interface LinksPluginOptions extends LinkOptions {
  links: string[];
  path: (file: ResolvedFile) => string;
}
```

`links()` повертає плагін, тож він стає до `plugins`, як будь-який інший, і ланцюжкові методи, такі як `.exclude()`, працюють з ним.

## Параметри {#options}

| Назва             | Тип                | Типово                   | Значення                                                                                                                                           |
| ----------------- | ------------------ | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `links`           | `string[]`         | required                 | Лінки, які треба визначити, за порядком.                                                                                                           |
| `path`            | `(file) => string` | required                 | Куди встановлюється кожен визначений файл. Викликається один раз для кожного файлу. Може містити змінні встановлення, такі як `${game_directory}`. |
| `githubToken`     | `string`           | none                     | Надсилається із запитами до API GitHub, коли збирання шукає реліз. Він підвищує ліміт запитів.                                                     |
| `gitlabToken`     | `string`           | none                     | Надсилається із запитами до API GitLab, коли збирання шукає файл пакета і коли завантажує його, щоб загешувати.                                    |
| `curseforgeToken` | `string`           | none                     | Обов’язковий для будь-якого лінка CurseForge. CurseForge не має анонімного API.                                                                    |
| `githubApi`       | `string`           | публічний API GitHub     | База API GitHub, для сервера, який не є публічним.                                                                                                 |
| `modrinthApi`     | `string`           | публічний API Modrinth   | База API Modrinth, для сервера, який не є публічним.                                                                                               |
| `curseforgeApi`   | `string`           | публічний API CurseForge | База API CurseForge, для сервера, який не є публічним.                                                                                             |

Функція `path` отримує `ResolvedFile`:

| Поле        | Значення                                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------ |
| `link`      | Лінк у тому вигляді, як ви його записали.                                                                    |
| `provider`  | `'github'`, `'gitlab'`, `'modrinth'`, `'curseforge'` або `'url'`.                                            |
| `filename`  | Назва файлу. Для звичайного URL це останній сегмент шляху, декодований, або хост, якщо URL не має шляху.     |
| `url`       | Звідки файл завантажується. Може відрізнятися від `link`.                                                    |
| `size`      | Розмір файлу в байтах.                                                                                       |
| `integrity` | Геш, як `{ sha256 }` або `{ sha1 }`. Відсутній лише коли Modrinth або CurseForge не наводить sha1 для файлу. |

## Лінки, які можна вставити {#links-you-can-paste}

opys читає кожен лінк за його хостом і шляхом. Щоб вирішити, чим є лінк, нічого не завантажується. Лінк, який не збігається з жодною формою нижче, вважається самим файлом. Рядок, який не є URL `http://` або `https://`, зупиняє збирання.

| Форма лінка                                                                        | Провайдер    | Звідки береться геш                                                                                                       |
| ---------------------------------------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------- |
| `github.com/<owner>/<repo>/releases/download/<tag>/<asset>`                        | `github`     | Дайджест GitHub для файлу релізу. Реліз без дайджеста завантажується і гешується.                                         |
| `github.com/<owner>/<repo>/releases/latest/download/<asset>`                       | `github`     | Те саме, на найновішому релізі, який не є чернеткою чи пререлізом і має файл. Переглядаються лише 100 найновіших релізів. |
| `<any host>/api/v4/projects/<project>/packages/generic/<package>/<version>/<file>` | `gitlab`     | `file_sha256` реєстру пакетів. Завантажується і гешується у рідкісному випадку, коли він відсутній.                       |
| `modrinth.com/…/version/<id>`                                                      | `modrinth`   | sha1 Modrinth для основного файлу версії.                                                                                 |
| `curseforge.com/…/files/<id>`                                                      | `curseforge` | sha1 CurseForge, коли він його публікує. Потребує `curseforgeToken`.                                                      |
| Будь-який інший `http://` або `https://` URL                                       | `url`        | Нічого не публікується, тож файл один раз завантажується під час збирання і гешується (sha256).                           |

Зауваги до форм:

- Лінк GitHub має точно збігатися з однією з двох форм вище. Сторінка репозиторію або сторінка `releases/tag/…` не є файлом, тож вона потрапляє до останнього рядка.
- Форма GitLab розпізнається на будь-якому хості, тож власний GitLab працює. Проєкт може бути шляхом, наприклад `group/name`, або числовим ідентифікатором.
- `www.` ігнорується, тож `www.curseforge.com` і `curseforge.com` це те саме.
- Токени використовуються під час збирання і ніколи не записуються до маніфесту. Інсталятор завантажує кожен `url` без нього, тож файл, для завантаження якого потрібен токен, не встановиться, хоча збирання могло його знайти.

::: warning Сторінка це не файл
Лінк, який не збігається з жодною формою, завантажується, і все, що повертається, фіксується. Сторінка проєкту Modrinth, наприклад `https://modrinth.com/mod/sodium`, не має сегмента `/version/`, тож вона не читається як версія. Вона завантажується як HTML, і цей HTML і є файлом. Посилайтеся на версію, як у `https://modrinth.com/mod/sodium/version/<id>`, або на власну адресу файлу.
:::

## Поведінка {#behaviour}

- **Визначається під час збирання.** Кожен лінк шукається, а кожен визначений файл фіксується, коли ви запускаєте `opys build`. Маніфест несе розмір, URL і геш. Машина встановлення ніколи не визначає лінк.
- **Лінк `latest` фіксується за релізом, який він означав того дня.** Перезберіть маніфест, щоб піти за новішим релізом.
- **Усе або нічого.** Якщо падає один лінк, збирання зупиняється. Часткового результату немає, тож маніфест ніколи не губить файл мовчки.
- **Лінки Modrinth і CurseForge групуються.** Кожного провайдера питають один раз про всі його лінки, як би вони не чергувалися в `links`. Інших провайдерів питають по одному лінку за раз.
- **Порядок зберігається.** Файли з’являються в маніфесті в тому порядку, в якому ви їх перелічили.
- **Один `path` для кожного лінка.** Функція однакова для кожного файлу в одному виклику `links()`. Щоб відправити частину файлів до іншої папки, розгалужуйтеся на `file.provider` або на `file.link` всередині функції або використайте другий виклик `links()` для тієї папки.

Лінк CurseForge без `curseforgeToken` це помилка, яка називає лінк. Тег GitHub, якого не знайдено, це помилка. Нею є й тегований реліз, який не має файлу з названим вами ім’ям, причому та помилка перелічує до восьми файлів, які реліз має, тож помилку в назві легко помітити.

Лінк `latest`, чий файл не несе жоден стабільний реліз, падає з `No stable GitHub release in <owner>/<repo> matching the loader filter`. Повідомлення каже «loader», хоча жоден завантажувач тут ні до чого, і воно не перелічує файли.

Зберіть його командою:

```sh
opys build
```

Конфігурація вище не потребує токена. Наступний фрагмент показує файл релізу GitHub і файл CurseForge, для збирання якого потрібен ваш ключ API. Кожен в окремому виклику `links()`, щоб вони могли мати різні папки. Він стає до списку `plugins` замість виклику `links()` вище:

```js
plugins: [
  fabric('1.21.1'),
  java('21'),
  links({
    path: (file) => '${game_directory}/resourcepacks/' + file.filename,
    links: [
      'https://github.com/owner/repo/releases/download/v1.2.0/pack.zip',
    ],
    githubToken: process.env.GITHUB_TOKEN,
  }),
  links({
    path: (file) => '${game_directory}/mods/' + file.filename,
    links: [
      'https://www.curseforge.com/minecraft/mc-mods/<slug>/files/6717445',
    ],
    curseforgeToken: process.env.CURSEFORGE_TOKEN,
  }),
],
```

`owner/repo`, `pack.zip` і `<slug>` це заглушки. Замініть перші два на справжній реліз. Для лінка CurseForge opys читає лише число після `/files/`, тож використовуйте адресу сторінки файлу.

Плагіни модів `modrinth` і `curseforge` роблять ту саму роботу для власних сайтів і приймають версію або ідентифікатор файлу, а не лінк. Читайте [Моди та файли](/uk/guide/mods), щоб зрозуміти, коли кожен з них кращий.

## Коли використовувати `files` натомість {#when-to-use-files-instead}

Використовуйте `links`, коли файл уже опубліковано і ви маєте його адресу. `links` фіксує геш, який дає видавець, або один раз гешує файл, якщо його не дає ніхто. Використовуйте [`files`](./files), коли файл лежить на вашому диску. Тоді нічого не опубліковано, а файл або везеться в бандлі, або хоститься вами.
