# fabric

`fabric()` додає завантажувач модів Fabric до інсталяції: гру, її бібліотеки та ресурси, а також власні бібліотеки Fabric й аргументи запуску. Назвіть версію Minecraft, і плагін вибере для неї збірку завантажувача Fabric, прочитає профіль лаунчера Fabric і накладе цей профіль на ванільну версію, від якої той успадковується. Використовуйте його замість `minecraft()`, оскільки `fabric()` уже додає ванільну гру, на якій будується, і поєднуйте його із [середовищем Java](./java). Ця сторінка для авторів модпаків. Про місце завантажувачів у конфігурації див. [Завантажувачі модів](/uk/guide/loaders).

## Сигнатура {#signature}

```ts
fabric(version: string, opts?: {
  loader?: string;
  source?: string;
  manifestBase?: string;
}): ChainablePlugin
```

`version` це єдиний обов’язковий аргумент. Виклик `fabric()` не виконує мережевої роботи; пошуки відбуваються, коли `opys build` або `opys launch` збирає конфігурацію. Він експортується з `@opys/minecraft` і з `@opys/fabric`.

## Версія {#version}

`version` це версія **Minecraft**, наприклад `'1.21.4'`. Збірка завантажувача Fabric не залежить від версії гри, тому завантажувач вибирають параметром `loader`, а не записом у `version`. Псевдонімів та ідентифікаторів збірок немає: `'1.21.4-best'` не є рядком версії для Fabric.

Без `loader` плагін запитує у Fabric Meta збірки завантажувача для `version` і бере найновішу стабільну. Якщо стабільної немає, він бере найновішу збірку з будь-якою стабільністю. Версія Minecraft, якої Meta не знає, завершує збирання з `HTTP 400` від Meta.

## Параметри {#options}

| Параметр       | Тип      | Типово                                                 | Значення                                                                                                                                   |
| -------------- | -------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `loader`       | `string` | Найновіша стабільна збірка завантажувача для `version` | Збірка завантажувача, наприклад `'0.16.10'`. Зафіксований завантажувач пропускає пошук найновішої збірки.                                  |
| `source`       | `string` | `https://meta.fabricmc.net`                            | Базова URL API Fabric Meta. Встановіть її для дзеркала.                                                                                    |
| `manifestBase` | `string` | Mojang `version_manifest_v2.json`                      | URL маніфесту версій Mojang, за яким завантажується ванільна версія, від якої успадковується профіль Fabric. Встановіть його для дзеркала. |

Зафіксуйте завантажувач, щоб мати збірку, яка не змінюється між збираннями:

```js
fabric('1.21.4', { loader: '0.16.10' });
```

Зафіксована збірка має існувати для тієї версії Minecraft. Збирання все одно завантажує профіль і ванільну версію.

## Групи запуску {#launch-groups}

Плагін називається `fabric`, тому його групи читаються як `fabric.<group>` у `manifest.command` і `manifest.args`.

| Група              | Тип      | Містить                                                                                                                                        |
| ------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `fabric.command`   | string   | `${java_bin}`, бінарний файл Java, який надає плагін [`java`](./java). У прикладах для `manifest.command` замість цього використано `java.bin` |
| `fabric.jvmArgs`   | `Valset` | Аргументи JVM: ванільні, з накладеними з профілю                                                                                               |
| `fabric.mainClass` | `Val`    | Головний клас із профілю Fabric, який замінює ванільний                                                                                        |
| `fabric.gameArgs`  | `Valset` | Ігрові аргументи: ванільні, з накладеними з профілю                                                                                            |

Поставте їх у `manifest.args` у порядку, потрібному грі:

```js
manifest: {
  command: ({ java }) => java.bin,
  args: ({ fabric }) => [fabric.jvmArgs, fabric.mainClass, fabric.gameArgs],
  workdir: '${game_directory}',
},
```

## Змінні {#variables}

`fabric()` визначає ті самі змінні, що й [`minecraft`](./minecraft#variables), з однією зміною: `classpath` зібрано для цієї збірки Fabric. Він містить бібліотеки Fabric, далі ванільні бібліотеки, які Fabric не замінює, далі клієнтський jar. `version_name` і `version_type` належать ванільній версії.

`root` дорівнює `.`, доки машина запуску його не встановить. `username`, `uuid` і `token` взагалі не визначені, тому їх має надати машина запуску. Як це зробити, пояснює сторінка [значень під час запуску](/uk/guide/run-client). `fabric()` не визначає `java_bin`, `java_home` чи `java_runtime_dir`. Їх визначає плагін [`java`](./java).

## Яка Java {#which-java}

Вибирайте версію Java за версією Minecraft. opys не перевіряє цю відповідність, тому невідповідність проявиться під час запуску гри, а не під час збирання.

| Версія Minecraft     | Java |
| -------------------- | ---- |
| 1.16.5 і старіші     | `8`  |
| від 1.17 до 1.20.4   | `17` |
| від 1.20.5 до 1.21.x | `21` |
| 26.x                 | `25` |

```js
plugins: [fabric('1.21.4'), java('21')],
```

## Як це працює {#how-it-works}

`fabric()` запитує у Fabric Meta найновішу стабільну збірку завантажувача для версії Minecraft (цей крок пропускається при зафіксованому `loader`) і завантажує профіль лаунчера цієї збірки. Профіль називає ванільну версію, від якої він успадковується. opys знаходить ту версію в маніфесті версій Mojang, завантажує її JSON версії та індекс ресурсів і відображає її тим самим кодом, який використовує плагін `minecraft`.

Далі профіль накладається на ванільну версію. Його бібліотеки стають у classpath попереду ванільних, тому гра завантажує копію бібліотеки від Fabric. Ванільна бібліотека, яку замінює бібліотека Fabric (та сама група й артефакт), вилучається з classpath і з завантажень. Аргументи профілю об’єднуються з ванільними, а його головний клас замінює ванільний. Бібліотеки Fabric надходять із Maven-репозиторію, названого в профілі, і кожна зафіксована за sha1 і розміром, які дає профіль; бібліотека без sha1 завантажується без хешу для перевірки.

Fabric не потребує нічого запускати на машині запуску перед стартом гри.
