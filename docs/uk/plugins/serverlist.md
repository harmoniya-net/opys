# serverlist

`serverlist` записує файл `servers.dat` гри, тож екран мережевої гри вже показує ваші сервери, коли гравець відкриває його вперше. Файл збирається зі списку, який ви передаєте, кодується у власному форматі гри і подорожує в бандлі, як будь-який інший файл.

## Сигнатура {#signature}

```ts
serverlist(servers: ServerEntry[], options?: ServerlistOptions): ChainablePlugin

interface ServerEntry {
  name: string;
  ip: string;
  rules?: RulesetInput;
}
```

Це плагін, тому йому місце в `plugins`. Він експортується з `@opys/minecraft` і з `@opys/minecraft-serverlist`, який також експортує `DEFAULT_PATH`, шлях, куди файл потрапляє, якщо ви його не змінили.

## Параметри {#options}

Кожен елемент `servers` приймає:

| Назва   | Тип            | Типово                 | Значення                                                                                                                            |
| ------- | -------------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `name`  | `string`       | немає, обов’язковий    | Підпис, показаний у списку.                                                                                                         |
| `ip`    | `string`       | немає, обов’язковий    | Адреса, до якої під’єднується гра, з портом, якщо він не типовий.                                                                   |
| `rules` | `RulesetInput` | немає: завжди у списку | Коли елемент діє. Приймає той самий скорочений запис, що й будь-яке правило, наприклад `'allow.os.linux'`. Див. попередження нижче. |

Другий аргумент приймає:

| Назва  | Тип      | Типово                            | Значення               |
| ------ | -------- | --------------------------------- | ---------------------- |
| `path` | `string` | `'${game_directory}/servers.dat'` | Куди записується файл. |

::: warning Елементи з `rules` поки що зберігаються не всі
Елементи групуються за набором правил, і кожна група записується в окремий `servers.dat`, захищений цим набором правил. Елементи без правил утворюють власну групу. Усі файли це артефакти за тим самим шляхом. Маніфест тримає один артефакт на шлях, тому коли у списку більше одного набору правил, залишається лише файл того набору, чий перший елемент стоїть у списку останнім. Решта елементів відкидається. Єдиний слід це лічильник злитих артефактів у журналі збирання, наприклад `(1 deduped)`.

Доки це не виправлено, давайте кожному елементу ті самі правила або жодних. Списку взагалі без `rules` це не стосується.
:::

## Що додає плагін {#what-it-contributes}

- **Один блоб-артефакт** для кожного набору правил у списку за шляхом `path`: байти файла лежать у бандлі, а не стягуються звідкись. Байти це нестиснутий NBT-документ, формат, який використовує `servers.dat`, з одним `name` і `ip` на елемент.
- **Один блоб**, що тримає ці байти, для кожного такого артефакту.
- **Жодних фрагментів запуску.** Плагін нічого не додає до командного рядка чи до `vars`.

Порожній список усе одно записує файл, але без серверів усередині. Він замінює той список, який був у гравця, і саме це означає передати жодного елемента.

Файл це артефакт, як і будь-який інший, і інсталяція звіряє його з хешем маніфесту, як і будь-який інший файл. Список, який гравець змінив, наприклад додавши сервер у грі, більше не збігається, тому при наступному встановленні чи запуску гри його буде повернуто до вашого.
