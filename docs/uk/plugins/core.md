# @opys/core

`@opys/core` це модель даних маніфесту: типи, з яких складається маніфест, функції, що читають і записують його, і бандл, яким він публікується. Звертайтеся до нього, коли ви читаєте, записуєте чи перевіряєте маніфест або коли плагін будує артефакти. Сам формат описано у [Маніфесті](/uk/reference/manifest) і [Бандлі](/uk/reference/bundle-format). Ця сторінка це API.

```sh
npm install @opys/core
```

Core це еталонна реалізація формату. Його функції це типізовані обгортки над нативним кодом. Його типи це звичайні дані, тож ви будуєте їх як звичайні об’єкти.

Експорти згруповано за призначенням.

## Маніфест {#manifest}

| Експорт          | Сигнатура                                                                    | Що робить                                                                                |
| ---------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `decodeManifest` | `(wire: unknown) => Manifest`                                                | Декодує об’єкт маніфесту з формату передавання, нормалізуючи його під час читання.       |
| `parseManifest`  | `(input: string) => Manifest`                                                | Розбирає рядок JSON у `Manifest`.                                                        |
| `encodeManifest` | `(domain: Manifest) => unknown`                                              | Кодує `Manifest` назад у формат передавання.                                             |
| `filterManifest` | `(manifest: Manifest, platform: OsOptions, features?: string[]) => Manifest` | Повертає маніфест без артефактів, чиї правила виключають їх на платформі й наборі ознак. |

`OsOptions` це `{ name, version, arch }`, усі рядки. Платформа записується як `{ name: 'linux', version: '', arch: 'x86_64' }`. Тип реекспортується з `@opys/mojang-rules`.

`filterManifest` фільтрує лише артефакти. Значення `vars` і `launch` повертаються як були, з умовними гілками на місці. Щоб прочитати запуск для платформи, використовуйте `resolvedArgs` і `resolvedEnvs` у розділі [Змінні та інтерполяція](#vars-and-interpolation).

| Тип        | Форма                                                                       |
| ---------- | --------------------------------------------------------------------------- |
| `Manifest` | `{ vars, launch?, artifacts, restrict? }`                                   |
| `Head`     | `Manifest` без `artifacts` плюс `format: number`. Це перший елемент бандла. |
| `Launch`   | `{ command, workdir, args: Valset, envs: ValDefs }`                         |

::: warning Кодування змінює деякі правила
Маніфест кодується функціями `encodeManifest` і `writeBundle`, а також збиранням, що повертає маніфест від `@opys/dev`. Кожна записує правило скорочено скрізь, де скорочення існує, і два випадки цього не переживають. Правило `os` з іменем і архітектурою водночас записується як `allow.os.<name>`, тож `arch` губиться. Правило з однією ознакою, встановленою в `false`, записується як `allow.features.<name>`, що вимагає увімкненої ознаки. На декодування це не впливає.
:::

## Артефакти і джерела {#artifacts-and-sources}

| Експорт                | Сигнатура                                               | Що робить                                                                                                        |
| ---------------------- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `sourceUrl`            | `(url: string) => Source`                               | Джерело в мережі.                                                                                                |
| `sourceBlob`           | `(blob: string) => Source`                              | Блоб, названий своїм sha256-ідентифікатором.                                                                     |
| `extractPick`          | `(file: string, into: string) => ExtractPick`           | Розпаковує один файл.                                                                                            |
| `extractScan`          | `(matches: string, into: string, opts?) => ExtractScan` | Розпаковує елементи, що збігаються з `matches`. Параметр `opts` приймає `strip`, `includes` і `excludes`.        |
| `extractDump`          | `(into: string, opts?) => ExtractDump`                  | Розпаковує весь архів. Параметр `opts` приймає `clean`, `includes` і `excludes`.                                 |
| `extractRules`         | `(artifact: Artifact) => readonly ExtractRule[]`        | Правила розпакування артефакту як список, хоч їх записано одним, хоч кількома.                                   |
| `deduplicateArtifacts` | `(artifacts: Artifact[]) => Artifact[]`                 | Відкидає дублікати за нормалізованим шляхом. Вміст пізнішого елемента перемагає, а місце він зберігає за першим. |

| Тип           | Форма                                                                                                                                                                      |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Artifact`    | `{ path, source, size?, rules?, integrity?, metadata?, extract? }`. Будь-який інший ключ відхиляється, коли артефакт декодується; для додаткових даних місце в `metadata`. |
| `Source`      | `{ url: string } \| { blob: string }`. Звужуйте через `'url' in source`.                                                                                                   |
| `Integrity`   | `HashEntry` або їхній список. `HashEntry` це `{ sha1 }`, `{ sha256 }` або `{ md5 }`.                                                                                       |
| `HashAlgo`    | `'sha1' \| 'sha256' \| 'md5'`                                                                                                                                              |
| `ExtractRule` | `ExtractPick \| ExtractScan \| ExtractDump`. Звужуйте за присутнім полем: `file` вибирає, `matches` сканує, інакше це дамп.                                                |

Артефакт, що називає блоб, не потребує `integrity`. Назва і є хешем.

::: warning Один об’єкт, один хеш
Записуйте кілька хешів як список однохешових об’єктів: `[{ sha1 }, { sha256 }]`. Один об’єкт із двома хешами, наприклад `{ sha1, sha256 }`, декодується лише з одним із них.
:::

## Блоби {#blobs}

Блоб це файл, який везе маніфест, названий за sha256 своїх байтів. Маніфест тримає лише ідентифікатор. Таблиця `Blobs` каже, де байти лежать на машині збирання, доки їх не буде записано в бандл.

| Експорт        | Сигнатура                                                 | Що робить                                                        |
| -------------- | --------------------------------------------------------- | ---------------------------------------------------------------- |
| `blobId`       | `(bytes: Uint8Array) => string`                           | Ідентифікатор блоба саме з цими байтами: їхній hex-рядок sha256. |
| `hashBlobFile` | `(path: string) => Promise<{ id: string; size: number }>` | Ідентифікатор і розмір блоба, яким став би файл на диску.        |
| `blobFile`     | `(file: string) => BlobSource`                            | Байти лежать у цьому файлі.                                      |
| `blobBytes`    | `(bytes: Uint8Array) => BlobSource`                       | Байти тримаються в пам’яті, збережені як base64.                 |

| Тип          | Форма                                                                        |
| ------------ | ---------------------------------------------------------------------------- |
| `BlobSource` | `{ file: string } \| { bytes: string }`, де `bytes` це base64.               |
| `Blobs`      | `Record<string, BlobSource>`, від ідентифікатора блоба до місця його байтів. |

```js
const { id, size } = await hashBlobFile('./server.jar');
const blobs = { [id]: blobFile('./server.jar') };
```

## Бандл {#the-bundle}

Бандл це zip, що тримає маніфест і його блоби. Елементи це `opys.json` (заголовок), `artifacts.json` і `blobs/<sha256>`. Функція `writeBundle` пише в тимчасовий файл поруч із `path` і переміщує його на місце, тож невдалий запис залишає наявний бандл як був.

| Експорт          | Сигнатура                                                            | Що робить                                                                                                                                                                           |
| ---------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `writeBundle`    | `(path: string, manifest: Manifest, blobs?: Blobs) => Promise<void>` | Записує бандл лише з тими блобами, які називає маніфест. Завершується помилкою, коли маніфест називає блоб, якого `blobs` не має, або чиї байти не дають його ідентифікатор у хеші. |
| `readBundle`     | `(path: string) => Manifest`                                         | Читає весь маніфест бандла. Завершується помилкою, коли формат той, який вона не читає, або коли маніфест називає блоб, якого бандл не має.                                         |
| `readBundleHead` | `(path: string) => Head`                                             | Читає лише заголовок. Список артефактів залишається непрочитаним.                                                                                                                   |
| `BUNDLE_FORMAT`  | `number`                                                             | Формат бандла, який ця збирання читає і записує.                                                                                                                                    |

```js
await writeBundle('server.opys', manifest, blobs);
const head = readBundleHead('server.opys'); // format, vars, launch, restrict
```

Розкладку описано у [Бандлі](/uk/reference/bundle-format).

## Змінні та інтерполяція {#vars-and-interpolation}

| Експорт        | Сигнатура                                                                              | Що робить                                                                                                    |
| -------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `valValues`    | `(val: Val) => string[]`                                                               | Рядки, які дає `Val`, у якому б написанні його не було записано. Використовуйте це замість читання `.value`. |
| `resolveVars`  | `(vars: Record<string, string>) => Record<string, string>`                             | Визначає посилання `${ref}` між змінними. Кидає помилку на циклічному посиланні.                             |
| `interpolate`  | `(template: string, vars: Record<string, string>) => string`                           | Підставляє змінні в шаблон.                                                                                  |
| `resolvedArgs` | `(launch: Launch, platform: OsOptions, features?: string[]) => string[]`               | Аргументи запуску, чиї правила виконуються на платформі й наборі ознак.                                      |
| `resolvedEnvs` | `(launch: Launch, platform: OsOptions, features?: string[]) => Record<string, string>` | Середовище запуску для платформи й набору ознак.                                                             |

`${name}`, якого немає в мапі, залишається в тексті як було, і в `resolveVars`, і в `interpolate`. Запис `\${` дає буквальне `${`. Функції `resolvedArgs` і `resolvedEnvs` застосовують лише правила: посилання `${...}` в тому, що вони повертають, не підставляються, тож пропустіть кожен рядок через `interpolate`. Для `resolvedEnvs` змінна з кількома гілками бере останню, чиї правила виконуються, а змінна без такої гілки пропускається.

`resolveVars` приймає плоску мапу рядків. Значення `vars` маніфесту можуть замість цього тримати умовні гілки, а в цьому пакеті немає функції, яка вибирає гілку для платформи; це робить рантайм, коли встановлює гру.

| Тип         | Форма                                                                                               |
| ----------- | --------------------------------------------------------------------------------------------------- |
| `ValDefs`   | `Record<string, string \| ConditionalVal[]>`. Змінна це рядок або список гілок `{ value, rules? }`. |
| `Val`       | `string \| ValObject`                                                                               |
| `ValObject` | `{ rules?, value: string \| string[] }`                                                             |
| `Valset`    | `Val[]`                                                                                             |

## Правила {#rules}

Правило в маніфесті можна записати двома способами, і обидва повноцінні. Ці дві назви позначають різницю.

| Назва                          | Де трапляється                             | Форма                                                                                                        |
| ------------------------------ | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `Rule` / `Ruleset`             | У маніфесті. Так правило записується.      | Скорочений рядок, наприклад `'allow.os.linux'`, або розгорнутий об’єкт. `Ruleset` це одне правило або масив. |
| `MojangRule` / `MojangRuleset` | Після розбору. Обчислювач приймає лише це. | Розгорнутий об’єкт. Реекспортується з `@opys/mojang-rules`.                                                  |

Скорочений запис це `allow` або `disallow`, потім крапка й одне з такого:

| Форма                                 | Значення                                                                                                                                           |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `os.<name>` або `os.<name>@<version>` | Значення `<name>` це `linux`, `windows` або `osx`. Текст після `@` це шаблон `version`, регулярний вираз, що шукається будь-де у версії платформи. |
| `features.<name>`                     | Правило вимагає увімкненої названої ознаки. Скорочення для вимкненої немає; використовуйте `disallow`.                                             |
| `arch.<arch>`                         | Значення `<arch>` це `x86`, `x86_64`, `arm`, `aarch64` або `any`.                                                                                  |

| Експорт             | Сигнатура                                                               | Що робить                                                                                                                                                                                                         |
| ------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `parseShortRuleset` | `(raw: Ruleset) => MojangRuleset`                                       | Розгортає обидва написання в канонічну форму. Кидає помилку на невідомій дії чи типі правила, невідомій назві ОС чи архітектурі або відсутніх назві ОС, ознаці чи архітектурі. Розгорнуте правило проходить як є. |
| `satisfiesRuleset`  | `(rules: Ruleset, platform: OsOptions, features?: string[]) => boolean` | Обчислює набір правил. Приймає обидва написання. Виконується, лише коли виконується кожне правило в ньому, а порожній набір виконується завжди.                                                                   |
| `emptyRuleset`      | реекспорт                                                               | З `@opys/mojang-rules`.                                                                                                                                                                                           |
| `allowOsRuleset`    | реекспорт                                                               | З `@opys/mojang-rules`.                                                                                                                                                                                           |

`satisfiesRuleset` спочатку розгортає скорочений запис, тому він ширший за строгий предикат Mojang. Для строгого використовуйте `@opys/mojang`. Правила описано у [@opys/mojang-rules](/uk/plugins/mojang-rules).

::: warning Як читається розгорнуте правило
Розгорнуте правило читається як правило `os`, якщо підходить, потім як правило `features`, потім як звичайні `allow` чи `disallow`. Правило, що має водночас `os` і `features`, зберігає лише `os`. Правило, чий `os` прочитати не вдається, наприклад із невідомим `name`, читається як звичайне правило і потім діє на кожній платформі. Скороченого запису це не стосується: невідома назва ОС у скороченні кидає помилку.
:::

```js
const rules = [
  'allow.os.linux',
  { action: 'disallow', features: { demo: true } },
];
satisfiesRuleset(rules, { name: 'linux', version: '', arch: 'x86_64' }); // true
```

## Glob-шаблони {#globs}

| Експорт             | Сигнатура                  | Що робить                                                                                                                                                               |
| ------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `globToRegex`       | `(glob: string) => RegExp` | Компілює glob-шаблон у `RegExp`, який має збігатися з усім рядком.                                                                                                      |
| `globToRegexSource` | `(glob: string) => string` | Джерело цього `RegExp` як рядок.                                                                                                                                        |
| `globBase`          | `(glob: string) => string` | Найдовший префікс каталогу в glob-шаблоні, у якому немає символу підстановки, без кінцевого `/`, або `''`, коли його немає. Використовуйте як місце початку прибирання. |

Роздільник це `/`. У glob-шаблоні:

| Шаблон  | Збігається з                                                                                                                   |
| ------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `*`     | Будь-який ряд символів, крім `/`.                                                                                              |
| `?`     | Один символ, крім `/`.                                                                                                         |
| `**`    | Будь-які символи, включно з `/`. Записи `**/` на початку, `/**/` всередині і `/**` у кінці також збігаються з нулем каталогів. |
| `{a,b}` | Будь-яка з альтернатив. Альтернативи це буквальний текст, а не шаблони.                                                        |

Кожен інший символ, включно з `.` і `[`, збігається сам із собою.
