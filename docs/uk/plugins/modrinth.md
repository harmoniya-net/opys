# modrinth

`modrinth` додає до пака файли модів, які ви називаєте на [Modrinth](https://modrinth.com/), а `modrinthModpack` додає цілий модпак з Modrinth: його завантажувач, його файли клієнтського боку та його перевизначення. Обидва експортуються з `@opys/minecraft` і не потребують ні облікового запису, ні ключа API. Використовуйте `modrinth`, коли самі вибираєте моди, і `modrinthModpack`, коли їх уже вибрав хтось інший.

```js
import { defineConfig } from '@opys/dev';
import { fabric, java, modrinth } from '@opys/minecraft';
```

Файл називають за його версією, а не за проєктом. Версія це один реліз мода, вона має ідентифікатор, наприклад `N08Z8wog`. Підійде й URL сторінки версії, тож ви можете вставити його просто з браузера.

## Сигнатури {#signatures}

```ts
modrinth(options: ModrinthPluginOptions): ChainablePlugin
modrinthModpack(ref: string, options?: ModrinthModpackOptions): ChainablePlugin
```

`modrinth` приймає один об’єкт, а `modrinthModpack` приймає посилання на модпак як перший аргумент і необов’язковий об’єкт після нього.

## `modrinth` {#modrinth-1}

| Назва      | Тип                | Типово                        | Значення                                                                                                                                                                                                                                                                                                |
| ---------- | ------------------ | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `versions` | `string[]`         | required                      | Версії, які треба встановити. Кожен запис це ідентифікатор версії, наприклад `'N08Z8wog'`, або URL версії, наприклад `'https://modrinth.com/mod/lithium/version/N08Z8wog'`. Кожна версія дає один файл: її основний файл або перший файл, якщо основний не позначено. Будь-який інший URL відхиляється. |
| `path`     | `(info) => string` | required                      | Викликається один раз для кожного файлу і повертає місце, куди файл потрапляє. Див. нижче.                                                                                                                                                                                                              |
| `apiBase`  | `string`           | `https://api.modrinth.com/v2` | Базовий URL API Modrinth. Змінюйте його лише для дзеркала.                                                                                                                                                                                                                                              |

Ідентифікатор версії, якого Modrinth не повертає, зупиняє збирання. Плагін встановлює лише ті файли, які ви перелічили, і нічого більше, тож власні залежності мода теж треба перелічити.

`path` отримує один об’єкт, який описує файл:

| Поле            | Тип      | Значення                                                                         |
| --------------- | -------- | -------------------------------------------------------------------------------- |
| `filename`      | `string` | Назва, яку файл має на Modrinth, наприклад `lithium-fabric-0.15.4+mc1.21.1.jar`. |
| `versionId`     | `string` | Ідентифікатор версії, наприклад `N08Z8wog`.                                      |
| `projectId`     | `string` | Ідентифікатор проєкту мода.                                                      |
| `versionNumber` | `string` | Версія у тому вигляді, як її пише Modrinth, наприклад `mc1.21.1-0.15.4-fabric`.  |
| `size`          | `number` | Розмір файлу в байтах.                                                           |

Рядок, який повертає `path`, використовується як шлях артефакту без змін. Запишіть у нього `${game_directory}` та інші змінні встановлення, і вони заповняться на машині запуску. Щоб покласти мод до папки `mods`, як роблять зазвичай, збережіть назву файлу:

```js
path: (info) => '${game_directory}/mods/' + info.filename,
```

`path` це звичайний JavaScript, тож одна версія може потрапити до іншої папки, ніж інша, або отримати нову назву. Він не може змінити, який файл завантажується: це завжди основний файл версії.

## `modrinthModpack` {#modrinthmodpack}

| Назва             | Тип                                     | Типово                                                         | Значення                                                                                                                                                                                                                                                                                                                                                                                              |
| ----------------- | --------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ref`             | `string`                                | required                                                       | Модпак, який треба встановити. Вкажіть ідентифікатор версії, наприклад `'fDlgR3Ps'`, URL версії, наприклад `'https://modrinth.com/modpack/fabulously-optimized/version/fDlgR3Ps'`, або прямий лінк на файл `.mrpack`. URL вважається самим файлом, якщо він закінчується на `.mrpack` або вказує на `cdn.modrinth.com`; будь-який інший URL має містити `/version/<id>`, інакше збирання зупиняється. |
| `options.apiBase` | `string`                                | `https://api.modrinth.com/v2`                                  | Базовий URL API Modrinth. Змінюйте його лише для дзеркала.                                                                                                                                                                                                                                                                                                                                            |
| `options.loader`  | `(spec: LoaderSpec) => ChainablePlugin` | Плагін opys для завантажувача пака, з його типовими значеннями | Викликається із завантажувачем, який просить пак. Його повернене значення це плагін, який використовується. Див. [параметр loader](#the-loader-option).                                                                                                                                                                                                                                               |

Якщо задано ідентифікатор версії, плагін бере файл `.mrpack` цієї версії. Якщо їх кілька, він бере основний або перший, якщо основний не позначено. Версія без файлу `.mrpack` зупиняє збирання.

## Що робить плагін модпака {#what-a-modpack-plugin-does}

`modrinthModpack` це плагін «усе в одному». Він бере власний завантажувач пака і піднімає його, тож вам не треба називати завантажувач самостійно. Під час збирання він:

1. **Читає пак.** Один раз завантажує `.mrpack` і читає його `modrinth.index.json`. Індекс називає версію Minecraft, завантажувач і кожен файл пака. Індекс без запису `minecraft` у `dependencies` зупиняє збирання.
2. **Вибирає завантажувач** з `dependencies` індексу і запускає відповідний плагін opys з версією, яку той називає. Той плагін також додає гру, бо завантажувач містить ванільний Minecraft. Відповідність така:

   | `dependencies` містить | Використаний плагін завантажувача                          |
   | ---------------------- | ---------------------------------------------------------- |
   | `fabric-loader`        | `fabric(minecraft, { loader: fabricLoader })`              |
   | `forge`                | `forge('<minecraft>-<forge>')`, наприклад `1.20.1-47.4.10` |
   | `neoforge`             | `neoforge(<neoforge>)`                                     |
   | жодного з цих          | `minecraft(minecraft)`, vanilla                            |
   | `quilt-loader`         | Не підтримується. Збирання зупиняється з помилкою.         |

3. **Додає файли клієнтського боку.** Кожен файл з індексу стає одним артефактом у `${game_directory}/<path>`, де `<path>` це шлях з індексу. Файли, які індекс позначає як `unsupported` на клієнті, пропускаються. Усе інше встановлюється, зокрема файли, які індекс позначає як `optional`.
4. **Додає перевизначення.** Сам `.mrpack` встановлюється до `${root}/cache/modrinth-modpack.mrpack`, а два його каталоги розпаковуються до `${game_directory}` без назви каталогу: спочатку `overrides/`, який отримують усі боки, потім `client-overrides/`, який отримує лише клієнт. Оскільки другий розпаковується останнім, він перемагає там, де обидва мають файл.
5. **Знову відкриває запуск.** `command`, `jvmArgs`, `mainClass` і `gameArgs` завантажувача доступні під `modrinthModpack`. Тож той самий блок `manifest` працює для пака на Fabric, Forge чи NeoForge.

Java не входить до пака. Файл `.mrpack` не називає JDK, тож додайте `java(...)` самостійно, з мажорною версією, якої потребує реліз Minecraft цього пака.

::: warning Quilt
Пак на Quilt провалює збирання, бо opys не має завантажувача Quilt. Шукайте натомість версію пака на Fabric або Forge.
:::

### Параметр `loader` {#the-loader-option}

`loader` замінює типовий плагін завантажувача. Він отримує специфікацію, яка є однією з таких:

| `spec.loader` | Поля                              | Типовий плагін                                |
| ------------- | --------------------------------- | --------------------------------------------- |
| `'fabric'`    | `minecraft`, `fabricLoader`       | `fabric(minecraft, { loader: fabricLoader })` |
| `'forge'`     | `version` (`<minecraft>-<forge>`) | `forge(version)`                              |
| `'neoforge'`  | `version`                         | `neoforge(version)`                           |
| `'vanilla'`   | `minecraft`                       | `minecraft(minecraft)`                        |

Використовуйте його, щоб дати завантажувачу власні параметри, наприклад дзеркало для його індексу документів. Типовий плагін не експортується, тож коли ви його замінюєте, пропишіть потрібні вам випадки. Заміна все одно має повертати плагін для кожної специфікації, бо пак може попросити будь-яку з них:

```js
import { fabric, forge, minecraft, neoforge } from '@opys/minecraft';

// mirror.example.com це заглушка для вашого власного дзеркала.
const forgeIndex = 'https://mirror.example.com/metadata/forge';

modrinthModpack('fDlgR3Ps', {
  loader: (spec) => {
    switch (spec.loader) {
      case 'fabric':
        return fabric(spec.minecraft, { loader: spec.fabricLoader });
      case 'forge':
        return forge(spec.version, { source: forgeIndex });
      case 'neoforge':
        return neoforge(spec.version);
      case 'vanilla':
        return minecraft(spec.minecraft);
    }
  },
});
```

## Як файли фіксуються {#how-files-are-pinned}

Кожен файл фіксується за гешем, який Modrinth наводить для нього, коли наводить. Інсталятор перевіряє завантажене за цим гешем.

- **Моди.** Артефакт несе sha1 файлу зі списку файлів версії та його розмір. Якщо Modrinth не наводить sha1 для файлу, артефакт не несе гешу.
- **Файли модпака.** Кожен артефакт несе sha1 з `hashes` індексу, коли індекс його має. `sha512` з індексу не використовується.
- **Перевизначення.** Файл `.mrpack` гешується під час збирання, за його sha1 та розміром. Інсталятор завантажує його знову і перевіряє байти за цим гешем, тож розпаковані перевизначення це ті, з яких читався індекс.

URL мода це той, який Modrinth наводить для файлу, на своєму CDN. URL файлу модпака це перший із `downloads` індексу. У будь-якому разі бандл тримає URL, тож встановлення відбувається без повторного звернення до API.

## Приклад {#example}

Ця конфігурація встановлює мод Lithium на Fabric для Minecraft 1.21.1. Lithium це невеликий широко вживаний мод для оптимізації, а ідентифікатор версії це той, що відповідає Lithium 0.15.4 на цій версії Minecraft:

<<< @/examples/plugin-modrinth-lithium/opys.config.mjs

Зберіть її командою `opys build`. Збирання записує `game.opys`, а список артефактів бандла має один запис для `lithium-fabric-0.15.4+mc1.21.1.jar` під `${game_directory}/mods/`, зафіксований за його sha1.

Модпаку потрібні лише його посилання, Java і той самий блок `manifest`, що вище, з `modrinthModpack` там, де був завантажувач:

```js
import { defineConfig } from '@opys/dev';
import { java, modrinthModpack } from '@opys/minecraft';

export default defineConfig({
  output: 'game.opys',
  plugins: [
    // Fabulously Optimized 5.1.0 для Minecraft 1.20.1.
    modrinthModpack('fDlgR3Ps'),
    java('17'),
  ],
  manifest: {
    command: ({ modrinthModpack }) => modrinthModpack.command,
    args: ({ modrinthModpack }) => [
      modrinthModpack.jvmArgs,
      modrinthModpack.mainClass,
      modrinthModpack.gameArgs,
    ],
    workdir: '${game_directory}',
  },
});
```

Цей приклад використовує Java 17 для Minecraft 1.20.1. Для іншого пака візьміть мажорну версію Java, якої потребує реліз Minecraft цього пака.
