# forge

`forge()` додає до інсталяції збірку Forge: гру, її бібліотеки та ресурси, а також власні бібліотеки Forge й аргументи запуску. Він приймає будь-яку збірку, яку публікує індекс, для кожної версії Minecraft, яку той перелічує, починаючи від 1.1, через один шлях коду. Ви називаєте версію Minecraft або збірку Forge, а решту визначає плагін. Використовуйте його замість `minecraft()`, бо `forge()` уже додає ванільну гру, на якій будується, і додайте поруч [середовище Java](./java). Ця сторінка для авторів паків.

## Сигнатура {#signature}

```ts
forge(version: string, opts?: {
  source?: string;
  manifestBase?: string;
}): ChainablePlugin
```

`version` є єдиним обов’язковим аргументом. Виклик `forge()` не виконує мережевих запитів; пошук відбувається тоді, коли `opys build` або `opys launch` збирає конфігурацію. Плагін експортується з `@opys/minecraft` і з `@opys/forge`.

## Версія {#version}

`version` має одну з трьох форм. Плагін пробує їх у такому порядку.

| Форма                         | Приклад                                              | У що визначається                       |
| ----------------------------- | ---------------------------------------------------- | --------------------------------------- |
| Псевдонім на версії Minecraft | `1.20.1-latest`, `1.20.1-recommended`, `1.20.1-best` | Це просування для цієї версії Minecraft |
| Версія Minecraft              | `1.20.1`                                             | Її збірка `best`                        |
| Ідентифікатор збірки          | `1.20.1-47.4.10`                                     | Саме ця збірка                          |

`latest` і `recommended` є власними просуваннями Forge. `best` означає `recommended`, коли версія Minecraft його має, і `latest` в іншому разі. Гола версія Minecraft означає `best`, тож `forge('1.20.1')` і `forge('1.20.1-best')` дають ту саму збірку. Багато версій Minecraft не мають збірки `recommended`, і для них `best` означає `latest`.

Гола версія Minecraft або псевдонім слідує за індексом, тож згодом може визначитися в новішу збірку. Назвіть ідентифікатор збірки, щоб зафіксувати одну.

Ідентифікатор збірки шукається в індексі, а не розбирається. Ідентифікатори Forge не мають єдиної форми: збірки 1.7.10 повторюють версію з обох кінців, як у `1.7.10-10.13.4.1614-1.7.10`. Використовуйте ідентифікатор так, як його перелічує Forge.

Якщо версію не вдається визначити, збирання зупиняється з одним з таких повідомлень:

| Повідомлення                                              | Причина                                                                       |
| --------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `Unknown Minecraft version '<mc>' (resolving '<input>')`  | Псевдонім на версії Minecraft, якої немає в індексі                           |
| `No '<alias>' Forge build available for Minecraft <mc>`   | Версія Minecraft не має збірки для такого псевдоніма, наприклад `recommended` |
| `Could not resolve Forge version '<input>' from <source>` | Ні версія Minecraft, ні ідентифікатор збірки з індексу                        |

## Параметри {#options}

| Параметр       | Тип      | Типово                                           | Значення                                                                                                                               |
| -------------- | -------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `source`       | `string` | `https://harmoniya-net.github.io/metadata/forge` | Базова адреса індексу документів. Вкажіть її для дзеркала.                                                                             |
| `manifestBase` | `string` | Маніфест `version_manifest_v2.json` від Mojang   | Адреса маніфесту версій від Mojang, за якою завантажується ванільна версія, від якої успадковує збірка Forge. Вкажіть її для дзеркала. |

```js
forge('1.20.1', { source: 'https://mirror.example.com/metadata/forge' });
```

## Групи запуску {#launch-groups}

Плагін має ім’я `forge`, тому його групи читаються як `forge.<group>` у `manifest.command` і `manifest.args`.

| Група             | Тип      | Містить                                                                                                                                      |
| ----------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `forge.command`   | string   | `${java_bin}`, бінарний файл Java, який дає плагін [`java`](./java). У прикладах для `manifest.command` замість нього використано `java.bin` |
| `forge.jvmArgs`   | `Valset` | Аргументи JVM для цієї збірки, включно з classpath і, для збірок на horno, властивостями `-Dhorno.*`                                         |
| `forge.mainClass` | `Val`    | Клас для старту. Див. нижче                                                                                                                  |
| `forge.gameArgs`  | `Valset` | Ігрові аргументи для цієї збірки                                                                                                             |

Головний клас залежить від збірки. Збірки, які працюють через horno, стартують з `net.harmoniya.horno.Main`, який потім встановлює Forge і запускає гру. Збірки для Minecraft від 1.6.2 до 1.12.2 стартують напряму з LaunchWrapper `net.minecraft.launchwrapper.Launch`. Вашій конфігурації не потрібно це знати: `forge.mainClass` містить правильний клас. Додайте групи до `manifest.args` у порядку, якого потребує гра:

```js
manifest: {
  command: ({ java }) => java.bin,
  args: ({ forge }) => [forge.jvmArgs, forge.mainClass, forge.gameArgs],
  workdir: '${game_directory}',
},
```

## Змінні {#variables}

`forge()` визначає ті самі змінні, що й [`minecraft`](./minecraft#variables), з однією зміною: `classpath` зібраний для цієї збірки Forge. Він тримає бібліотеки збірки, а потім ванільні бібліотеки, які збірка не замінює. Ванільний клієнтський jar іде останнім, хіба що збірка сама перелічує клієнтський jar як бібліотеку, як це робить кожна збірка через horno. `version_name` і `version_type` належать ванільній версії.

`root` є `.`, доки машина запуску не вкаже інше. Машина запуску має надати `username`, `uuid` і `token`, бо вони взагалі не визначені. Як це зробити, каже сторінка [значень під час запуску](/uk/guide/run-client). `forge()` не визначає `java_bin`, `java_home` чи `java_runtime_dir`. Їх визначає плагін [`java`](./java).

## Яка Java {#which-java}

Вибирайте версію Java за версією Minecraft. opys не перевіряє цю відповідність, тому невідповідність проявиться під час старту гри, а не під час збирання.

| Версія Minecraft     | Java |
| -------------------- | ---- |
| 1.16.5 і старіші     | `8`  |
| від 1.17 до 1.20.4   | `17` |
| від 1.20.5 до 1.21.x | `21` |
| 26.x                 | `25` |

Дві збірки потребують версії поза цією таблицею:

- **1.7.2** старіша за Java 8 і не стартує на ній. Використайте Java 7 від Zulu: `java('7', { vendor: 'zulu' })`. Zulu публікує Java 7 лише для `x86_64`.
- **1.16.4** читає внутрішній клас JDK, який змінив випуск Java 8u321. Використайте випуск Java 8 до цього оновлення, наприклад `java('8u312-b07')`. Типовий постачальник, Temurin, його надає.

```js
plugins: [forge('1.7.2'), java('7', { vendor: 'zulu' })],
```

## Як це працює {#how-it-works}

Кожна збірка Forge опублікована як документ версії за адресою `harmoniya-net.github.io/metadata/forge`. Індекс там перелічує кожну версію Minecraft та її збірки, а кожна збірка має документ, який каже, як її запускати, у формі документа версії від Mojang, що успадковує ванільну версію. Коли ви називаєте версію, плагін читає індекс, читає документ, завантажує ванільну версію, від якої документ успадковує, і накладає їх одне на одне. Бібліотеки Forge стають перед ванільними, а ванільна бібліотека, яку замінює бібліотека Forge, зникає з classpath і з завантажень. Клієнтський jar іде останнім, крім випадків, коли документ сам його перелічує: тоді цей запис стає замість нього, а `${version_dir}/client.jar` ні не завантажується, ні не входить до classpath.

Forge встановлюється кількома способами. Збірки від 1.13.2 потребують запуску процесорів Forge, а джар-модам від 1.1 до 1.5.2 потрібне перезаписане клієнтське jar. Обидві дії відбуваються на машині запуску, в [horno](/uk/internals/horno), перед стартом гри. Документ оголошує horno бібліотекою і називає його головним класом. Для збірки з процесорами аргументи `-Dhorno.*` називають інсталятор Forge, його адресу та його SHA-1, і horno запускає процесори інсталятора. Для збірки з джар-модом вони називають виправлене клієнтське jar для створення та клас для подальшого старту. Збірки для версій від 1.6.2 до 1.12.2 не потребують horno і стартують напряму з LaunchWrapper. Сторінка [метаданих](/uk/internals/metadata) описує документи та їхнє створення.

::: tip
Тут нічого не потрібно налаштовувати. Плагін записує аргументи документа в маніфест, а решту робить лаунчер.
:::
