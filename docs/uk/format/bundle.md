# Файл бандла

Бандл це спосіб зберігання маніфесту: zip із фіксованою структурою. Ця
сторінка описує цю структуру для всіх, хто читає або пише бандл без opys.

Про те, для чого бандл, дивіться [Бандл](/uk/basics/bundle).

## Записи

| Запис            | Містить                                |
| ---------------- | -------------------------------------- |
| `opys.json`      | **Заголовок**: що бандл каже про себе. |
| `manifest.json`  | [Маніфест](./), цілий.                 |
| `blobs/<sha256>` | Один запис на перенесений файл.        |

```sh
unzip -l game.opys
unzip -p game.opys opys.json
unzip -p game.opys manifest.json | jq '.launch'
```

**Чому два файли JSON:** вони описують різні речі. Маніфест описує
встановлення, він важить мегабайти, по одному запису на встановлений
файл. Заголовок описує бандл, він малий. Він тримає `format` і
`options`.

Шукайте записи за ім'ям. Не покладайтеся на їхній порядок.

## format

```json
{ "format": 1 }
```

Версія формату, у заголовку. Вона дорівнює `1`.

Читач має:

- Читати `format` **спочатку**.
- Відхилити бандл, якщо це не ціле `1`. Відсутнє, `"1"` і `1.0`
  усе відхиляється.
- Зробити це до читання `manifest.json`.

**Чому спочатку:** інший формат може інакше писати маніфест. Читач,
що вгадує, міг би встановити не те.

Читач ігнорує будь-яке інше поле заголовка.

**Будь-яке інше число відхиляється**, менше так само, як більше. opys
читає один формат. Немає ні перенесення, ні режиму сумісності. Коли
формат змінюється, бандл перезбирається з конфігурації командою
`opys build`.

Для лаунчера це означає: оновіть рантайм і перевидайте бандли разом.

## options

Що той, хто запускає бандл, може вибрати. Необов'язкове, у заголовку.

```json
{
  "format": 1,
  "options": [
    {
      "slider": "xmx",
      "title": "RAM",
      "min": 1024,
      "max": 16384,
      "step": 512,
      "default": 4096,
      "unit": "MB"
    },
    {
      "feature": "custom_java",
      "title": "Custom Java",
      "options": [{ "directory": "java_home", "title": "Java folder" }]
    }
  ]
}
```

Маніфест читає змінні й перевіряє прапорці. `options` каже, які з них
гравець може задати і як питати кожне. Це лише схема: встановлювач її
не читає, а вибране гравцем доходить до встановлення як прості `vars`
і `features`.

Параметр налаштувань буває одного з шести видів. Поле, що називає вид,
тримає й ім'я:

| Поле        | Ім'я це   | Значення це           |
| ----------- | --------- | --------------------- |
| `slider`    | змінна    | число в діапазоні     |
| `select`    | змінна    | одне зі списку        |
| `text`      | змінна    | рядок тексту          |
| `file`      | змінна    | шлях файла            |
| `directory` | змінна    | шлях теки             |
| `feature`   | прапорець | ввімкнено чи вимкнено |

Кожен параметр має `title` і може мати `subtitle`. Решта залежить від
виду:

| Вид       | Обов'язкове                     | Необов'язкове            |
| --------- | ------------------------------- | ------------------------ |
| `slider`  | `min`, `max`, `step`, `default` | `unit`                   |
| `select`  | `choices`, `default`            |                          |
| `text`    |                                 | `placeholder`, `default` |
| `feature` |                                 | `default`, `options`     |

- `default` це число на повзунку, рядок на виборі чи в тексті, і логічне
  значення на прапорці. Прапорець без `default` вимкнений.
- `choices` це список `{ "value", "label" }`, у порядку показу.
- `options` прапорця це параметри, що важливі, лише поки він увімкнений.
  Вони самі можуть бути прапорцями, на будь-яку глибину.

Читач відхиляє заголовок, чиї налаштування:

- не називають жодного виду або називають більше одного;
- несуть поле іншого виду, наприклад `min` на виборі;
- називають одну змінну двічі або один прапорець двічі будь-де в дереві;
- мають повзунок із `min` не менше `max`, `step` не більше нуля або
  `default` поза діапазоном;
- мають вибір, чий `default` не є `value` одного з його варіантів.

**Чому в заголовку:** лаунчер показує налаштування ще до будь-якого
встановлення, а заголовок читається без маніфесту.

## Блоби

Блоб це файл, перенесений у бандлі. Артефакт називає його за sha256
його вмісту:

```json
{
  "path": "${game_directory}/config/pack.toml",
  "source": { "blob": "f727f7b2…" }
}
```

Його байти це запис `blobs/f727f7b2…`. Id це 64 малі шістнадцяткові
цифри.

Читач має:

- Відхилити бандл, що називає блоб, якого він не містить, **до
  будь-якого встановлення**.
- Перевірити кожен блоб за його ім'ям під час його встановлення.

Письменник не має зберігати байти під ім'ям, до якого вони не хешуються.
Той самий блоб, використаний двома артефактами, зберігається один раз.

## Що записує opys

Так поводиться еталонний письменник. Читач не має на це покладатися.

- `opys.json` першим і без стиснення, щоб читався з початку файла.
  Решта стиснена.
- Блоби за порядком їхніх id.
- Фіксовані мітки часу, тож той самий маніфест завжди дає ті самі записи.
- Жодних інших записів. Читач ігнорує ті, яких не знає.

## Читання

```text
open the zip
head = json(entry "opys.json")
if head.format != 1: refuse
manifest = json(entry "manifest.json")
for each artifact with source.blob:
    if no entry "blobs/" + id: refuse
```

Далі, під час встановлення артефакту з блобом: скопіюйте запис у його
`path` і відхиліть його, якщо його sha256 не є id.

## Ім'я файла

За домовленістю `<name>.opys`. Від нього в форматі нічого не залежить.
