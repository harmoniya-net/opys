# Java

Ця сторінка описує плагін `java()`: як він дає грі JDK, як вибрати його версію і постачальника і яка Java потрібна кожній версії Minecraft. Ви використовуєте його в кожному модпаку, і типово про нього не треба думати далі за номер версії.

## Що він робить {#what-it-does}

`java('21')` додає середовище Java до маніфесту. Він нічого не встановлює на вашому комп’ютері. Типово він визначає JDK для Linux, macOS і Windows, кожної на `x86_64` і `aarch64`, і пропускає платформу, для якої постачальник не має збірки. Архів кожної платформи стає артефактом з правилом ОС і архітектури, тож гравець завантажує тільки той JDK, який відповідає його комп’ютеру. Інсталятор розпаковує його до `${java_runtime_dir}/jdk-21/`.

Плагін володіє трьома змінними і однією групою запуску:

| Назва                 | Що це                                                         |
| --------------------- | ------------------------------------------------------------- |
| `java_runtime_dir`    | Каталог, куди розпаковуються JDK. Типово `${root}/runtimes`.  |
| `java_home`           | Кореневий каталог JDK. На macOS він містить `/Contents/Home`. |
| `java_bin`            | Виконуваний файл `java` всередині нього.                      |
| `bin` (група запуску) | Те саме, що `java_bin`. Використовуйте його для `command`.    |

Спрямуйте `command` на групу запуску, щоб гра стартувала на JDK, який надав плагін:

```js
plugins: [forge('1.20.1'), java('17')],
manifest: {
  command: ({ java }) => java.bin,
  // args, workdir ...
},
```

Плагін також експортує `JAVA_HOME` в середовище запуску зі значенням `${java_home}`. Інструменти, які стартують під час запуску, наприклад лаунчер відеокарти, знаходять JDK саме так.

::: tip Фіксуйте версію, а не шлях
Ніколи не записуйте шлях до JDK на власному диску в `manifest`. Маніфест один для всіх гравців, а `java_home` вже вказує правильний шлях на кожній машині. Про значення, які справді належать машині запуску, див. [Значення під час запуску](./run-client).
:::

### Куди розпаковується JDK {#where-the-jdk-is-unpacked}

`java_runtime_dir` йде за `root`, тож JDK переїжджають разом з рештою інсталяції. Щоб покласти їх в інше місце, задайте змінну. Шлях на машині гравця, наприклад `/opt/jdks`, є значенням під час запуску і належить до `runClient`, а не до `manifest.vars`:

```js
runClient: (manifest) => ({
  vars: { ...manifest.vars, java_runtime_dir: '/opt/jdks' },
}),
```

Завантажені архіви теж лежать у `java_runtime_dir`, поруч із розпакованим каталогом `jdk-<major>/`. Залиште їх там. Інсталятор розпаковує архів знову при кожному встановленні, тож вилучений архів завантажиться знову.

### Windows {#windows}

На Windows `java_bin` типово вказує на `javaw.exe`, тож гра працює без вікна консолі. Передайте `opys launch` або `opys install` ознаку `--feature java_console`, щоб використати натомість `java.exe`, і ви бачили вивід гри в терміналі:

```sh
opys launch --feature java_console
```

## Вибір версії {#choosing-a-version}

Перший аргумент це версія, рядок. Передайте мажорну версію, щоб отримати останній реліз цієї мажорної версії, або передайте точну збірку, щоб отримати саме її. Як виглядає точна збірка, залежить від постачальника:

| Постачальник | Мажорна версія | Точна збірка    | Оновлення Java 8 |
| ------------ | -------------- | --------------- | ---------------- |
| `temurin`    | `'21'`         | `'21.0.12.1+1'` | `'8u312-b07'`    |
| `zulu`       | `'21'`         | `'21.0.12'`     | `'8.0.312'`      |
| `graalvm`    | `'21'`         | `'21.0.2'`      | Недоступно       |

Деталі для кожного постачальника:

- **Temurin** приймає назву релізу так, як її пише Adoptium: `'21.0.12.1+1'` для Java 9 і новіших, `'8u312-b07'` для Java 8. Ви можете додати префікс `jdk-` або `jdk8u`, а суфікс `-LTS` при мажорній версії ігнорується. Неповна назва, наприклад `'21.0.12'`, ні з чим не збігається.
- **Zulu** передає версію у фільтр `java_version` Azul без змін, тож значення треба писати так, як його пише Azul. Мажорна версія на кшталт `'7'` підходить, і точкова версія на кшталт `'21.0.12'` або `'8.0.312'` теж підходить. Azul може відповісти довшою версією, ніж ви написали: `'21.0.12'` повертає JDK `21.0.12.1`.
- **GraalVM CE** приймає мажорну версію, яка вибирає найновіший реліз `jdk-<major>.*`, або точкову версію, з якої він складає тег `jdk-<version>`. Підтримується тільки стандартна каденція релізів `jdk-<major>.<minor>.<patch>`. Інноваційний тег на кшталт `graal-25.2.4` відхиляється під час збирання.

Якщо жоден реліз не збігається, збирання падає з помилкою `No <vendor> binaries found for version '…'`. Звірте написання з власним списком релізів постачальника.

::: warning Zulu ігнорує версію, яку не може прочитати
API Azul не відхиляє `java_version`, якого не розуміє. Воно відповідає натомість своїм найновішим JDK. Виклик `java('8u312-b07', { vendor: 'zulu' })`, а це написання Adoptium, збирається без помилки і дає найновіший Zulu, а не Java 8. Прочитайте рядок `[java]`, який друкує збирання, наприклад `[java] Zulu 8.58.0.13 (JDK 8.0.312)`, і перевірте, що він називає той JDK, який ви мали на увазі.
:::

## Постачальники {#vendors}

Виберіть постачальника опцією `vendor`. Типовий постачальник це `temurin`.

| `vendor`    | Дистрибутив                      | Джерело                                   |
| ----------- | -------------------------------- | ----------------------------------------- |
| `'temurin'` | Eclipse Temurin, проєкт Adoptium | API Adoptium                              |
| `'zulu'`    | Azul Zulu                        | API метаданих Azul                        |
| `'graalvm'` | GraalVM Community Edition        | Релізи GitHub `graalvm/graalvm-ce-builds` |

GraalVM тут означає Community Edition, зібраний з `graalvm/graalvm-ce-builds`. Власна дистрибуція GraalVM від Oracle не входить до варіантів.

```js
java('7', { vendor: 'zulu' });
java('21', { vendor: 'graalvm' });
```

## Опції {#options}

Другий аргумент приймає такі опції. Повний список з типами наведено на [сторінці плагіна `java`](/uk/plugins/java).

| Опція       | Для чого                                                                                                                                                                                                   |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vendor`    | `'temurin'` (типово), `'zulu'` або `'graalvm'`.                                                                                                                                                            |
| `platforms` | Платформи, для яких надається JDK, як пари `{ os, arch }`. Поле `os` це `'linux'`, `'osx'` або `'windows'`; поле `arch` це `'x86_64'` або `'aarch64'`. Типово всі три системи, кожна на обох архітектурах. |
| `apiBase`   | Інша адреса API. Для Temurin і Zulu дзеркало їхнього API. Для GraalVM хост GitHub Enterprise.                                                                                                              |
| `token`     | Токен GitHub для вищого ліміту частоти. Тільки GraalVM.                                                                                                                                                    |

Плагін падає під час збирання, а не під час запуску, коли жоден реліз не відповідає версії. JDK завжди фіксується хешем sha256, тож гравець ніколи не отримає неперевірений JDK.

::: warning Спершу викликайте з версією
Правильно писати `java('17')`. Виклик `java({ version: '17' })` кидає `TypeError`, щойно виконується конфігурація, бо версія є першим аргументом.
:::

## Яка Java для якої версії Minecraft {#which-java-for-which-minecraft-version}

Користуйтеся таблицею нижче. Починаючи з 1.7.2 її рядки це мажорні версії Java з власних метаданих версій Mojang для кожного релізу, крім 1.17 і 1.17.1, які Mojang наводить з 16 і які також працюють на 17.

| Версія Minecraft     | `java(…)` |
| -------------------- | --------- |
| від 1.0 до 1.16.5    | `'8'`     |
| від 1.17 до 1.20.4   | `'17'`    |
| від 1.20.5 до 1.21.x | `'21'`    |
| 26.x                 | `'25'`    |

Cleanroom (1.12.2) і lwjgl3ify (1.7.10) не йдуть за таблицею. Обидва існують для того, щоб старий Minecraft працював на сучасній Java, і беруть `'25'`.

Дві збірки Forge потребують Java поза таблицею:

- **Forge 1.7.2** вийшов раніше за Java 8 і не стартує на ній. Він працює на Java 7, яку Temurin не публікує, тож ви просите її в Zulu:

  ```js
  java('7', { vendor: 'zulu' });
  ```

- **Forge 1.16.4** читає нутрощі JDK, які змінилися в Java 8u321. Візьміть останнє оновлення перед цією зміною:

  ```js
  java('8u312-b07');
  ```

Жодне з них не є обмеженням opys. Обидва походять із самих збірок Forge.
