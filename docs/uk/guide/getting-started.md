# Перші кроки

Ця сторінка проведе вас від порожнього каталогу до запущеної гри, а далі до
модпака на Forge. Достатньо Node.js 20 або новішої версії, більше нічого не
потрібно: Java opys завантажить сам.

## Встановлення {#install}

```sh
npm install -g @opys/cli
mkdir my-pack && cd my-pack
npm init -y
npm install -D @opys/dev @opys/minecraft
```

Команда `opys` глобальна, а ваша конфігурація це звичайний модуль JavaScript,
імпорти якого беруться з вашого проєкту. Тому ці два пакети встановлено
локально, так само як конфігурація Vite знаходить свої плагіни.

Створіть `opys.config.mjs`:

<<< @/examples/vanilla/opys.config.mjs

Варто спершу поглянути на три частини:

- **`plugins`** описують, з чого складається інсталяція. `minecraft('1.21.1')`
  додає гру, її бібліотеки та ресурси; `java('21')` додає середовище Java для
  будь-якої машини, на якій гру встановлюють.
- **`manifest`** описує запуск. Кожен плагін повертає свої частини, а ви
  складаєте їх у потрібному порядку: бінарний файл Java, далі аргументи JVM,
  головний клас і аргументи гри.
- **`runClient`** надає те, що знає лише машина запуску: куди встановлювати і
  хто грає. Докладніше див. [Значення під час запуску](./run-client).

## Запуск {#launch-it}

```sh
opys launch
```

Перший запуск завантажує близько гігабайта: гру, її ресурси та JDK. Наступні
запуски звіряють файли, які вже є на диску, і довантажують лише відсутнє або
змінене.

Усе потрапляє до каталогу, шлях до якого повертає `userDataDir('my-pack')`:
`~/.local/share/my-pack` на Linux, `%APPDATA%\my-pack` на Windows,
`~/Library/Application Support/my-pack` на macOS. Щоб почати спочатку,
видаліть його.

::: tip Гра в офлайн-режимі
`token: '0'` запускає гру без облікового запису Microsoft, цього достатньо для
одиночної гри та серверів в офлайн-режимі. Про вхід гравців див.
[Акаунти, сервери, відеокарти](./extras).
:::

## Модпак на Forge {#make-it-a-forge-pack}

Замініть завантажувач і підберіть до нього версію Java:

<<< @/examples/forge/opys.config.mjs{2,6,9}

`forge('1.20.1')` вибирає збірку, яку індекс Forge позначає як найкращу для
цієї версії Minecraft: рекомендовану, якщо вона є, інакше останню. Аргументи
тепер надходять від `forge`, бо спосіб запуску гри визначає завантажувач.
NeoForge, Fabric та інші працюють так само; див.
[Завантажувачі модів](./loaders).

Щоб додати моди, покладіть їх у папку `mods` поруч із конфігурацією і додайте
один плагін:

```js
import { files } from '@opys/dev';

// ...
plugins: [
  forge('1.20.1'),
  java('17'),
  files({ from: 'mods', to: '${game_directory}/mods/${rel}' }),
],
```

Кожен файл із `mods` встановлюється до каталогу `mods` гри. У зібраному бандлі
ці файли подорожують усередині нього, тому окремий хостинг їм не потрібен.

Або вкажіть їх там, де їх опубліковано, на Modrinth чи CurseForge, і нехай opys
зафіксує кожен файл: див. [Моди та файли](./mods).

## Файл для поширення {#build-something-to-share}

```sh
opys build
```

Ця команда записує `game.opys`, один файл з описом усієї інсталяції. Будь-хто з
opys може запустити його без вашої конфігурації та вашого проєкту:

```sh
opys launch game.opys --var root=/path/to/install --var username=Player \
  --var uuid=00000000-0000-0000-0000-000000000001 --var token=0
```

Бандл не має `runClient`, бо конфігурація це код, а бандл це дані, тож значення
для конкретної машини передаються через `--var`. Лаунчер, який ви напишете
самі, передає їх так само: див. [Вбудовування рантайму](/uk/launcher/embedding).
