# Основні поняття

В opys є чотири ідеї. Коли вони стануть зрозумілими, решта документації буде
деталями.

## Маніфест описує інсталяцію {#a-manifest-describes-an-installation}

**Маніфест** це перелік файлів і командний рядок. Кожен файл, який тут зветься
**артефактом**, каже, куди він потрапляє, звідки береться і який геш він мусить
мати. Командний рядок каже, як запустити гру, коли файли вже на місці.

```json
{
  "artifacts": [
    {
      "path": "${library_directory}/com/mojang/brigadier/1.3.10/brigadier-1.3.10.jar",
      "source": {
        "url": "https://libraries.minecraft.net/…/brigadier-1.3.10.jar"
      },
      "integrity": { "sha1": "d15b53a14cf20fdcaa98f731af5dda654452c010" }
    }
  ],
  "launch": {
    "command": "${java_bin}",
    "args": ["-cp", "…", "net.minecraft.client.main.Main"],
    "workdir": "${game_directory}"
  }
}
```

Маніфест **повністю визначений**. Він ніколи не каже «останній Forge» або
«запитай у цього сервера, який файл забрати». Кожен артефакт називає один
конкретний файл, а там, де геш можна отримати, фіксує його. З’ясувати, які
файли і які геші потрібні, це одноразова робота на момент збирання маніфеста.

Тому встановлення просте і безпечне: завантажити, перевірити, розпакувати,
запустити. Інсталятор не ухвалює рішень і не довіряє жодному серверу
розповідати йому, що правильне. Щоб підхопити оновлення, ви збираєте новий
маніфест.

## Бандл це спосіб перевезти маніфест {#a-bundle-is-how-a-manifest-travels}

Деякі файли не мають URL: написана вами конфігурація, приватний мод. Такі
файли їдуть поруч із маніфестом як **блоби**, кожен названо за sha256 його
вмісту.

**Бандл** це zip, який тримає маніфест і його блоби. Це той один файл, який
записує `opys build`, і той один файл, який потрібен лаунчеру. Оскільки це
звичайний zip, його відкриє будь-який інструмент:

```sh
unzip -l game.opys
#   opys.json        заголовок: format, vars, launch, restrict
#   artifacts.json   перелік артефактів
#   blobs/<sha256>   один елемент на кожен файл, що везеться
```

Точну розкладку описано в [форматі бандла](/uk/reference/bundle-format).

## Маніфест збирають плагіни {#plugins-build-the-manifest}

Маніфест ніхто не пише вручну. **Плагін** додає його частину:
`forge('1.20.1')` з’ясовує, які бібліотеки потрібні цій збірці Forge і де живе
кожна, `java('17')` знаходить JDK для кожної платформи, `modrinth(…)` фіксує
названі вами файли модів.

Плагін додає щось із чотирьох речей: артефакти (з блобами, які вони везуть),
змінні, змінні середовища і частини команди запуску. Ваша конфігурація
перелічує плагіни, а потім складає ці частини докупи:

```js
plugins: [forge('1.20.1'), java('17')],
manifest: {
  command: ({ java }) => java.bin,
  args: ({ forge }) => [forge.jvmArgs, forge.mainClass, forge.gameArgs],
},
```

Плагіни працюють лише під час збирання. На машині, яка встановлює результат,
від плагіна нічого немає, тому лаунчеру потрібен лише малий рантайм, а не весь
інструментарій.

## Дві машини, і що належить кожній {#two-machines-and-what-belongs-to-each}

Це та ідея, через яку трапляються помилки, коли її пропускають.

|                | Машина збирання                 | Машина запуску                     |
| -------------- | ------------------------------- | ---------------------------------- |
| Хто            | Ви, коли виконуєте `opys build` | Гравець, коли запускає гру         |
| Запускає       | Плагіни                         | Рантайм                            |
| Знає           | Версії, моди, геші              | Свої шляхи, обліковий запис гравця |
| Визначається в | `plugins`, `manifest`           | `runClient`, або `--var`           |

Усе, що лежить у `manifest`, запікається в бандл і однакове для кожного
гравця. Тому шлях на вашому диску, ваше ім’я користувача чи токен доступу
ніколи не кладуть туди. Це **значення під час запуску**, і їх надає машина
запуску щоразу, коли гра стартує.

Змінні це те місце, де зустрічаються дві половини. Маніфест каже
`${library_directory}/…`, яке будується з `${root}`, а машина запуску каже,
чому дорівнює `root`. Змінні, які маніфест залишає відкритими, перелічено в
[розділі Змінні](/uk/launcher/vars).

Коли ви виконуєте `opys launch` із конфігурації, ваш комп’ютер це обидві
машини водночас, що зручно і що також легко приховує різницю між ними.
`runClient` і тоді залишається половиною запуску.

## Як частини відповідають пакетам {#how-the-pieces-map-to-packages}

| Хто ви                     | Чим ви користуєтеся                                    |
| -------------------------- | ------------------------------------------------------ |
| Пишете модпак              | `@opys/cli`, `@opys/dev`, `@opys/minecraft`            |
| Пишете лаунчер             | `@opys/runtime`                                        |
| Пишете плагін              | `@opys/dev`, `@opys/core`                              |
| Читаєте бандли іншою мовою | [Формат](/uk/reference/bundle-format), і більше нічого |

Сторона збирання і рантайм ніколи не залежать одне від одного. Формат
маніфеста це єдине, що їх пов’язує, і це стабільна частина: пакети,
API плагінів і прапорці командного рядка можуть змінюватися, а формат
змінюється лише навмисно.
