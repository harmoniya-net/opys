# Завантажувачі модів

Ця сторінка допоможе вам вибрати завантажувач модів для модпака і правильно записати його рядок версії. Тут описано шість ігрових плагінів з `@opys/minecraft`: ванільний `minecraft`, `forge`, `neoforge`, `fabric`, `cleanroom` і `lwjgl3ify`. Для кожного з них ви знайдете допустимі значення рядка версії, групи запуску, які можна підставити в `manifest.args`, і Java, з якою його варто поєднувати.

Завантажувач визначає, як стартує гра: головний клас, аргументи JVM перед ним і бібліотеки у classpath. Тож виберіть його спершу, а потім зберіть `args` з того самого плагіна.

## Короткий огляд {#at-a-glance}

| Завантажувач                      | Для чого                                       | Версії Minecraft                                                 | Рядок версії                                                             | Java                            |
| --------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------- |
| [`minecraft`](#minecraft-vanilla) | Гра в тому вигляді, в якому її постачає Mojang | Будь-який ідентифікатор версії Mojang                            | Точний ідентифікатор або нічого для останнього релізу                    | За версією, див. [нижче](#java) |
| [`forge`](#forge)                 | Моди під Forge                                 | Кожна версія Minecraft з індексу Forge, від 1.1                  | Версія Minecraft, псевдонім або ідентифікатор збірки                     | За версією, з двома винятками   |
| [`neoforge`](#neoforge)           | Моди під NeoForge                              | Кожна версія Minecraft з індексу NeoForge, від 1.20.2            | Версія Minecraft, псевдонім або ідентифікатор збірки                     | За версією                      |
| [`fabric`](#fabric)               | Моди під Fabric                                | Будь-яка версія Minecraft, для якої Fabric Meta має завантажувач | Версія Minecraft; щоб зафіксувати збірку завантажувача, вкажіть `loader` | За версією                      |
| [`cleanroom`](#cleanroom)         | Cleanroom, наступник Forge для 1.12.2          | `1.12.2`                                                         | Версія Minecraft, псевдонім або тег релізу                               | 25                              |
| [`lwjgl3ify`](#lwjgl3ify)         | lwjgl3ify, Forge 1.7.10 на LWJGL 3             | `1.7.10`                                                         | Версія Minecraft, псевдонім або тег релізу                               | 25                              |

Cleanroom і lwjgl3ify існують для того, щоб старий Minecraft працював на сучасній Java, тому обидва беруть 25. Правило для решти наведено в [розділі про Java](#java).

## Рядки версій {#version-strings}

Forge, NeoForge, Cleanroom і lwjgl3ify публікують кожен свій індекс збірок. Їхні рядки версій визначаються в однаковому порядку:

1. Псевдонім до версії Minecraft: `1.20.1-latest`, `1.20.1-recommended` або `1.20.1-best`.
2. Сама версія Minecraft без нічого, що означає її збірку `best`.
3. Повний ідентифікатор збірки, наприклад `1.20.1-47.4.10`.

`best` означає збірку `recommended`, якщо вона є, і `latest` у протилежному разі. Що саме означає `recommended`, залежить від завантажувача. Для Forge це власне просування Forge. Для NeoForge це найновіша збірка, чий ідентифікатор не має кваліфікатора на кшталт `-beta`. Для Cleanroom і lwjgl3ify це найновіший реліз, який GitHub не позначив як пререліз.

Деякі версії Minecraft не мають збірки `recommended`. Сама версія все одно визначається, у збірку `latest`, а от запит псевдоніма `-recommended` для такої версії завершиться помилкою.

Індекс вирішує, до якої версії Minecraft належить збірка, а не рядок. Ідентифікатори збірок шукають, а не розбирають, бо в них немає нічого, що надійно називало б версію Minecraft.

Fabric і ванільний клієнт є винятками. Їхній `version` приймає тільки версію Minecraft і жодних псевдонімів.

## Групи запуску {#launch-groups}

Кожен плагін завантажувача додає ті самі чотири групи під власним ім’ям. Використовуйте їх у `manifest.args` ось так:

```js
args: ({ neoforge }) => [
  neoforge.jvmArgs,
  neoforge.mainClass,
  neoforge.gameArgs,
],
```

| Група              | Вміст                                                            |
| ------------------ | ---------------------------------------------------------------- |
| `<name>.jvmArgs`   | Аргументи JVM, які потрібні завантажувачу, перед головним класом |
| `<name>.mainClass` | Головний клас для запуску                                        |
| `<name>.gameArgs`  | Аргументи, які отримує гра                                       |
| `<name>.command`   | Команда запуску завантажувача                                    |

`<name>.command` це текст `${java_bin}`, змінна, яку задає плагін `java`, тобто те саме значення, що й `java.bin`. У прикладах використано `java.bin`, а `<name>.command` лишається незадіяним.

Групи це звичайні значення, а порядок в `args` задаєте ви. Між ними можуть стояти інші аргументи.

## Minecraft (ванільний) {#minecraft-vanilla}

`minecraft` встановлює гру так, як її публікує Mojang, без завантажувача поверх. Використовуйте його, щоб грати у ванільну гру або як основу для модпака, куди ви додаєте моди вручну.

Його рядок версії це точний ідентифікатор версії Mojang, наприклад `1.21.1` або `26.3`. Псевдонімів немає. Викличте його без версії, щоб узяти поточний реліз:

```js
minecraft(); // останній стабільний реліз, визначається під час збирання
```

Він надає `minecraft.command`, `minecraft.jvmArgs`, `minecraft.mainClass` і `minecraft.gameArgs`. Його єдина опція, крім версії, це `manifestBase` для дзеркала Mojang. Повний приклад:

## Forge {#forge}

`forge` встановлює Forge для будь-якої версії, яку він публікує, від модів під jar часів 1.1 до поточних збірок, одним кодовим шляхом.

Його рядок версії приймає три форми з розділу [Рядки версій](#version-strings). Наприклад, `forge('1.20.1')` бере збірку `best` для 1.20.1, `forge('1.20.1-latest')` бере найновішу, а `forge('1.20.1-47.4.10')` називає одну збірку точно. Ідентифікатор збірки часів 1.7 довший, наприклад `1.7.10-10.13.4.1614-1.7.10`, бо він повторює версію Minecraft на обох кінцях.

Він надає `forge.command`, `forge.jvmArgs`, `forge.mainClass` і `forge.gameArgs`. Його опції це `source`, індекс документів, і `manifestBase`. Конфігурація така, як показано в розділі [Перші кроки](/uk/guide/getting-started#make-it-a-forge-pack), а плагін описано на [окремій сторінці](/uk/plugins/forge).

Forge поєднується з Java за версією, крім двох збірок, які потребують фіксації. Див. [розділ про Java](#java).

## NeoForge {#neoforge}

`neoforge` встановлює NeoForge. Його індекс публікується окремо від індексу Forge, а ідентифікатори збірок зовсім не схожі на ідентифікатори Forge.

Його рядок версії приймає версію Minecraft, три псевдоніми і ідентифікатор збірки NeoForge, наприклад `21.1.172`. Збірка з кваліфікатором, наприклад `-beta`, ніколи не буває `recommended`, тому версія Minecraft, яка має лише такі збірки, визначається у свою збірку `latest`. Ідентифікатор збірки не називає версію Minecraft, а свіжий ідентифікатор на кшталт `26.2.0.84` належить до Minecraft `26.2` без початкового `1.`, тож його шукають, а не читають.

Він надає `neoforge.command`, `neoforge.jvmArgs`, `neoforge.mainClass` і `neoforge.gameArgs`. Його опції це `source` і `manifestBase`, ті самі, що й у Forge. Повний приклад:

## Fabric {#fabric}

`fabric` встановлює Fabric. Його `version` це завжди версія Minecraft, а збірку завантажувача Fabric вибирають окремо.

Без опції `loader` плагін `fabric` бере найновішу стабільну збірку завантажувача, яку Fabric Meta наводить для цієї версії Minecraft, або просто найновішу збірку, якщо жодну не позначено стабільною. Зафіксуйте конкретну опцією `loader`, щоб лишатися на ній:

```js
fabric('1.21.4', { loader: '0.16.10' }),
```

Зафіксована збірка має існувати для цієї версії Minecraft, інакше збирання впаде з помилкою HTTP від Fabric Meta. Fabric не приймає псевдонімів, тож `1.21.4-best` не є для нього рядком версії.

Він надає `fabric.command`, `fabric.jvmArgs`, `fabric.mainClass` і `fabric.gameArgs`. Його опції це `loader`, `source` (Fabric Meta, типово `https://meta.fabricmc.net`) і `manifestBase`. Повний приклад:

## Cleanroom {#cleanroom}

`cleanroom` встановлює [Cleanroom](https://github.com/CleanroomMC/Cleanroom), наступника Forge для 1.12.2 на сучасній JVM. Його індекс має одну версію Minecraft, `1.12.2`.

Його рядок версії приймає `1.12.2`, три псевдоніми і точний тег релізу, наприклад `0.6.13-alpha`. Тег релізу не називає версію Minecraft, тож його шукають в індексі, як і кожен ідентифікатор збірки.

Він надає `cleanroom.command`, `cleanroom.jvmArgs`, `cleanroom.mainClass` і `cleanroom.gameArgs`. Його єдина опція, крім версії, це `source`. Жоден інсталятор не запускається, ні під час збирання, ні під час запуску: реліз публікує повний документ версії, і opys читає саме його.

Cleanroom потребує JDK 25. Див. [розділ про Java](#java). Плагін описано на [окремій сторінці](/uk/plugins/cleanroom).

## lwjgl3ify {#lwjgl3ify}

`lwjgl3ify` встановлює [lwjgl3ify](https://github.com/GTNewHorizons/lwjgl3ify), варіант Forge 1.7.10 на LWJGL 3. Його індекс має одну версію Minecraft, `1.7.10`.

Його рядок версії приймає `1.7.10`, три псевдоніми і точний тег релізу, наприклад `3.0.37`. Як і для Cleanroom, тег шукають в індексі.

Він надає `lwjgl3ify.command`, `lwjgl3ify.jvmArgs`, `lwjgl3ify.mainClass` і `lwjgl3ify.gameArgs`. Разом з ним приходять дві речі, яких ви не просили:

- **UniMixins** додається до `mods/`, бо без нього lwjgl3ify не завантажується. Передайте `unimixins: false`, щоб не додавати його, для модпака, який приносить власне середовище міксинів. Опція `unimixins` також приймає `{ version, repo }`, щоб вибрати інший реліз.
- **Jar мода lwjgl3ify** додається до `mods/` з його релізів GitHub.

GitHub обмежує анонімні запити, тож передайте `token`, якщо збирання падає з обмеженням частоти. Решта опцій це `source`, `repo` (репозиторій, звідки береться jar мода) і `apiBase`. Плагін описано на [окремій сторінці](/uk/plugins/lwjgl3ify).

## Java {#java}

Поєднайте завантажувач із `java(...)` з `@opys/minecraft` і виберіть його версію за версією Minecraft:

| Версія Minecraft    | Java |
| ------------------- | ---- |
| від 1.0 до 1.16.5   | 8    |
| від 1.17 до 1.20.4  | 17   |
| від 1.20.5 і новіші | 21   |
| 26.x                | 25   |

Починаючи з 1.7.2 це ті мажорні версії Java, які наведено у власних метаданих версій Mojang, крім 1.17 і 1.17.1, які Mojang наводить з 16 і які також працюють на 17.

Дві збірки Forge потребують фіксації:

- Forge 1.7.2 вийшов раніше за Java 8. Він працює на Java 7:
  `java('7', { vendor: 'zulu' })`.
- Forge 1.16.4 читає нутрощі JDK, які змінилися в Java 8u321. Йому потрібне останнє оновлення перед цією зміною: `java('8u312-b07')`.

Cleanroom і lwjgl3ify беруть 25 незалежно від версії Minecraft.

opys не перевіряє пару. Java, на якій гра не може працювати, впаде під час старту гри, а не під час збирання. Про те, як постачається середовище і які постачальники доступні, див. [Java](/uk/guide/java).
