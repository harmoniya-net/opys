# Моди та файли

Ця сторінка описує, як моди й інші файли потрапляють до модпака. Шляхів чотири, і кожен закінчується однаково: артефактом у маніфесті, зафіксованим хешем. Якщо слова «артефакт», «блоб» або «бандл» для вас нові, спершу прочитайте [Основні поняття](./concepts).

## Вибір джерела {#choosing-a-source}

| Джерело      | Коли використовувати                                                                                                                  | Звідки беруться байти                               | Плагін                               |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------ |
| `modrinth`   | Мод є на Modrinth і ви знаєте його версію                                                                                             | CDN Modrinth; хеш з API Modrinth                    | [modrinth](/uk/plugins/modrinth)     |
| `curseforge` | Мод є на CurseForge                                                                                                                   | CDN CurseForge; потрібен токен API                  | [curseforge](/uk/plugins/curseforge) |
| `links`      | У вас є URL: файл релізу GitHub або GitLab, версія Modrinth або сторінка файла CurseForge, чи будь-яка адреса, з якої віддається файл | Звідти, куди вказує посилання                       | [links](/uk/plugins/link)            |
| `files`      | Файл лежить у вас на диску: приватний мод, згенерована конфігурація                                                                   | Всередині бандла або за адресою `url`, яку ви даєте | [files](/uk/plugins/files)           |

Перші три називають файл, який публікує хтось інший. Плагін `files` бере файл, який маєте ви. Якщо мод є на платформі, надайте перевагу плагіну платформи: його хеш надходить з платформи, і вам не треба шукати його самим. Використовуйте `links` для одиничного URL, а `files` для всього, що взагалі не опубліковане.

Щоб встановити цілий модпак, а не окремі моди, використовуйте `modrinthModpack` або `curseforgeModpack`. Їх описано на сторінках [modrinth](/uk/plugins/modrinth) і [curseforge](/uk/plugins/curseforge).

## Modrinth {#modrinth}

Називайте кожен мод його версією, або як ідентифікатор версії, або як URL сторінки версії. Ідентифікатор це сегмент після `/version/` у такому URL, як у `https://modrinth.com/mod/sodium/version/JjCVwmVA`. opys передає цей сегмент до Modrinth як ідентифікатор, тож URL, який несе натомість номер версії, наприклад `…/version/mc1.21.1-0.8.12-beta.2-fabric`, завершує збирання помилкою `HTTP 400`. Така конфігурація збирає Fabric-модпак з двома модами з Modrinth:

<<< @/examples/mods-modrinth/opys.config.mjs

Кожна версія додає свій основний файл або перший файл, якщо жодного не позначено основним. Плагін `modrinth` не потребує токена: API Modrinth відкрите.

opys бере кожну версію так, як ви її назвали. Він не звіряє версію з вашим завантажувачем або версією Minecraft, тож вибрана версія має відповідати модпаку. У прикладі вище використано версії для 1.21.1 під `fabric('1.21.1')`.

## CurseForge {#curseforge}

Плагін `curseforge` приймає числові ідентифікатори файлів або URL файла на CurseForge. Йому потрібен ключ API з [консолі CurseForge](https://console.curseforge.com/), переданий як `token`. Читайте ключ зі змінних середовища, а не записуйте його в конфігурацію, щоб конфігурацію можна було комітити:

```js
curseforge({
  token: process.env.CURSEFORGE_TOKEN,
  path: (file) => `\${game_directory}/mods/${file.filename}`,
  files: [
    6717445, // ідентифікатор файла або URL його сторінки на CurseForge
  ],
}),
```

Додайте його до `plugins` поруч із завантажувачем і `java`, як у прикладі з Modrinth. Запустіть збирання з ключем у вашому шеллі:

```sh
CURSEFORGE_TOKEN=your-key opys build
```

Ключ використовується тільки під час збирання. URL, які він визначає, публічні, тож зібраний бандл встановлюється без нього. Усі опції плагіна наведено на його власній сторінці.

## Посилання {#links}

Плагін `links` бере URL і перетворює його на зафіксований файл. Ви можете вставити посилання, яке вже маєте. Кожне посилання визначається під час збирання, а хеш записується до маніфесту:

| Посилання                                                                                                    | Звідки береться хеш                                                                                    |
| ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `github.com/<owner>/<repo>/releases/download/<tag>/<asset>`                                                  | Дайджест, який GitHub наводить для файла релізу. Для файла без нього opys завантажує файл і хешує його |
| `github.com/<owner>/<repo>/releases/latest/download/<asset>`                                                 | Так само, на найновішому релізі, який не є пререлізом і має цей файл                                   |
| `<host>/api/v4/projects/<project>/packages/generic/<package>/<version>/<file>`, файл реєстру пакунків GitLab | sha256, про який повідомляє реєстр                                                                     |
| `modrinth.com/…/version/<id>`                                                                                | sha1 від Modrinth                                                                                      |
| `curseforge.com/…/files/<id>`                                                                                | sha1 від CurseForge. Потрібен `curseforgeToken`                                                        |
| Будь-який інший URL                                                                                          | Один раз завантажується під час збирання, потім хешується                                              |

Додайте `links` до `plugins` так само, як додаєте `modrinth`:

```js
links({
  path: (file) => `\${game_directory}/mods/${file.filename}`,
  links: [
    'https://modrinth.com/mod/sodium/version/JjCVwmVA',
    'https://github.com/owner/repo/releases/latest/download/mod.jar',
    'https://example.com/files/custom-mod.jar',
  ],
  curseforgeToken: process.env.CURSEFORGE_TOKEN,
}),
```

Друге і третє посилання це заглушки; дайте плагіну `links` адреси файлів, які існують.

Посилання `latest` фіксується до того релізу, який є найновішим на момент збирання. Воно не стежить за релізом далі. Переберіть бандл, щоб перейти на новіший.

::: warning Сторінка це не файл
Адреса Modrinth або CurseForge, яка не називає версію чи файл, наприклад `https://modrinth.com/mod/lithium`, трактується як будь-який інший URL. opys завантажує те, що лежить за цією адресою, а тут це вебсторінка проєкту, хешує її і встановлює під цією назвою. Вставте посилання на конкретну версію або файл.
:::

Токени необов’язкові, крім посилань CurseForge. Опція `githubToken` підвищує ліміт частоти GitHub і відкриває приватні репозиторії. Опція `gitlabToken` відкриває приватні проєкти GitLab.

## Файли на вашому диску {#files-on-your-disk}

Плагін `files` бере каталог на машині збирання і створює артефакт для кожного звичайного файла під ним, хоч би як глибоко він лежав; за символічним посиланням він не йде. Поле `from` задається відносно файла конфігурації. Плагін `files` експортується з `@opys/dev`, а не з `@opys/minecraft`. Форми дві, і яка вам дістанеться, залежить від того, чи ви дали `url`.

**Перенесення в бандлі.** Без `url` кожен файл зберігається в бандлі як блоб, названий за sha256 його вмісту:

```js
files({ from: 'mods', to: '${game_directory}/mods/${rel}' });
```

Команда `opys build` записує блоби в бандл. Команда `opys launch` читає їх звідти, де вони є, без попереднього копіювання. Щоб ці файли встановилися, їх ніде не треба хостити.

**Вказівка на URL, який хостите ви.** З `url` бандл не несе копії. Кожен артефакт вказує на файл за цією адресою, зафіксований своїм хешем. Файли ви завантажуєте самі:

```js
files({
  from: 'mods',
  to: '${game_directory}/mods/${rel}',
  url: 'https://cdn.example/${rel}',
  hash: 'sha256', // необов’язково; типово sha1
});
```

Кожен файл хешується, назвали ви хеш чи ні, тож змінений файл підтягується знову. Використовуйте форму з перенесенням, якщо тільки ви не хочете хостити файли окремо від бандла.

### Розміщення файлів через `to` і `url` {#placing-files-with-to-and-url}

Для плагіна `files` поле `to` каже, куди лягає кожен файл, а поле `url` каже, де лежить його копія. Кожне з них приймає або рядок шаблону, або функцію від файла.

Як рядок шаблону, такі заповнювачі підставляються для кожного файла:

| Змінна        | Значення                                                            |
| ------------- | ------------------------------------------------------------------- |
| `${rel}`      | Шлях відносно `from`, з роздільниками `/`                           |
| `${dir}`      | Частина `${rel}` з каталогом. Порожня для файлів на верхньому рівні |
| `${filename}` | Останній сегмент шляху                                              |

Будь-яке інше `${name}` лишається як є до моменту встановлення, тож `${game_directory}` і `${root}` працюють у шаблоні `to`. Повний список див. у розділі [Змінні](/uk/launcher/vars).

::: warning Дайте `to` змінну
Без `to` шляхом файла стає сам `${rel}`, наприклад `settings.txt`, без жодної змінної спереду. Ніщо не прив’язує такий шлях до гри, тож він відлічується від місця, звідки працює інсталятор. Починайте `to` зі `${game_directory}` або `${root}`.
:::

Як функція, ви отримуєте ті самі три поля, а також `abs`, повний шлях файла на машині збирання, і `size`, його розмір у байтах. Функція може вирішувати місце для кожного файла в будь-який потрібний вам спосіб:

```js
files({
  from: 'mods',
  to: (file) => `\${game_directory}/mods/${file.filename}`,
});
```

Плагін `files` повертає плагін, який можна звузити ланцюжковими методами з `@opys/dev`, наприклад `.exclude(...)`. Повний список опцій див. на сторінці [files](/uk/plugins/files).

### Розміщення модів через `path` {#placing-mods-with-path}

Плагіни `modrinth`, `curseforge` і `links` приймають натомість функцію `path`, а не шаблон. Вона викликається один раз для кожного визначеного файла і повертає місце, куди лягає файл. Вона може використовувати змінні моменту встановлення, наприклад `${game_directory}`, так само, як шаблон `to`.

Що отримує функція:

| Плагін       | Поля                                                          |
| ------------ | ------------------------------------------------------------- |
| `modrinth`   | `filename`, `versionId`, `projectId`, `versionNumber`, `size` |
| `curseforge` | `filename`, `fileId`, `projectId`, `size`                     |
| `links`      | `link`, `provider`, `filename`, `url`, `size`, `integrity`    |

Кожен плагін приймає один `path`. Щоб покласти файли до другої папки, наприклад папки пакета ресурсів, додайте другий екземпляр плагіна з власним `path`.

## Фіксація під час збирання {#pinned-at-build-time}

Кожен файл, який використовує модпак, фіксується хешем під час збирання, а запуск уже нічого не визначає. Хеш надходить з платформи, де файл опубліковано, а де її немає, з читання файла засобами opys. Посилання `latest` визначається так само. Бандл каже, які байти встановлювати, а не де шукати найсвіжіші.

Звідси випливає, що інсталяція може містити тільки ті файли, які ви зібрали. Це також означає, що ви не оновите мод, змінивши модпак на машині гравця. Щоб оновити:

1. Змініть ідентифікатор версії, посилання або файл у вашому проєкті.
2. Знову виконайте `opys build`. Це запише новий бандл.
3. Опублікуйте новий бандл. Див. [Публікація бандла](./publishing).

::: warning
Гравці лишаються з модами зі встановленого бандла, доки не встановлять новий. Перезбирання змінює вашу копію, а не їхню.
:::
