# Помилки

Ця сторінка описує помилки, які кидає `@opys/runtime`, що кожна з них повідомляє і що лаунчер має з ними робити. Вона для розробника лаунчера, який обробляє відхилення `install`, `prepare` або `launch`. Про події прогресу, що передують помилці, див. [Прогрес](./progress).

Кожна помилка, яку називає рантайм, це `RuntimeError`. Три види мають власні поля, і вони є підкласами. Розгалужуйтеся за полем `code`, а поля читайте, лише коли підтвердили вид.

::: warning Не аналізуйте повідомлення
Поле `message` це англійський текст, написаний для людей, які читають лог. Його формулювання може змінитися в будь-якому релізі. Нічого не має збігатися з ним, і нічого в `@opys/runtime` так не робить. Використовуйте `code`, клас і поля.
:::

## RuntimeError {#runtimeerror}

```ts
class RuntimeError extends Error {
  readonly code: RuntimeErrorCode;
  // повідомлення, ім’я ('RuntimeError') і причина, як у будь-якої помилки Error
}

type RuntimeErrorCode =
  | 'network'
  | 'integrity'
  | 'extraction'
  | 'manifest'
  | 'io'
  | 'cancelled'
  | 'other';
```

Підкласи нижче розширюють `RuntimeError`, тому `instanceof RuntimeError` істинне для кожного з них, а `err.code` завжди задано.

## Підкласи {#subclasses}

| Class             | `code`       | Fields                  |
| ----------------- | ------------ | ----------------------- |
| `NetworkError`    | `network`    | `url`, `status`, `body` |
| `IntegrityError`  | `integrity`  | `paths`                 |
| `ExtractionError` | `extraction` | `artifactPath`, `cause` |

- **`NetworkError`**: `url` це адреса, яку запитували. `status` це HTTP статус, який повернув сервер, і `0`, коли відповіді взагалі не було, наприклад при відхиленому з’єднанні або передачі, що обірвалася на півдорозі. `body` це те, що надіслав сервер, коли він щось надіслав, і порожній рядок інакше. Для передачі, що обірвалася, поле `body` тримає опис помилки від транспорту.
- **`IntegrityError`**: `paths` перелічує файли, вміст яких не збігся з гешем, який фіксує маніфест. Шляхи це кінцеві шляхи на диску, зі вже підставленими змінними. Під час одного встановлення можуть не пройти перевірку кілька файлів, і перелічують усі.
- **`ExtractionError`**: `artifactPath` це архів, який не вдалося розпакувати, точно так, як його пише маніфест, тобто змінні на кшталт `${root}` не підставлено. Поле `cause` це звичайний `Error`, повідомлення якого каже чому, наприклад що архів не чинний zip або що ціль не каталог. Читайте `err.cause.message`. У TypeScript поле `cause` має тип `unknown`, тому спершу звузьте його до `Error`.

Лише ці три мають власні поля. Інші коди це звичайні `RuntimeError`, включно з `io`. Див. зауваження під таблицею нижче.

## Коди {#codes}

| `code`       | Class             | Meaning                                                                                                           | What the launcher should do                                                                                                                                                                                                                                                                                                                                              |
| ------------ | ----------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `network`    | `NetworkError`    | Завантаження не вдалося: сервер його відхилив, або з’єднання не вдалося чи обірвалося                             | **Повторіть пізніше.** Рантайм уже спробував кожен файл чотири рази, з очікуванням 0.5, 2 і 8 секунд між спробами, тому помилка надходить приблизно за десять секунд після першої невдачі. Перед наступною спробою зачекайте довше. Значення `404` або `410` означає, що на сервері більше немає файла, названого в маніфесті: **зберіть** бандл заново замість повтору. |
| `integrity`  | `IntegrityError`  | Завантажений або скопійований файл не збігається з гешем, який фіксує маніфест                                    | **Повторіть один раз**, бо пошкоджена передача часто вдається з другої спроби. Якщо знову не вдасться, сервер віддає інші байти, ніж зафіксувала збірка: **зберіть** заново.                                                                                                                                                                                             |
| `extraction` | `ExtractionError` | Архів не вдалося розпакувати                                                                                      | **Прочитайте `cause`.** Якщо архів пошкоджено, **зберіть** заново. Якщо причина у файловій системі, наприклад немає місця чи немає прав, сприймайте це як `io`.                                                                                                                                                                                                          |
| `manifest`   | `RuntimeError`    | Маніфест або бандл, у якому він надійшов, не вдалося прочитати, або він називає блоб, якого нічого не тримає      | **Зберіть** заново або попросіть новіший лаунчер, якщо бандл у форматі, якого цей не знає. Повтор не допоможе.                                                                                                                                                                                                                                                           |
| `io`         | `RuntimeError`    | Файлова система щось відхилила: немає місця, немає прав, поганий шлях, файл бандла, якого немає                   | **Скажіть гравцеві** з причиною з повідомлення, щоб він її прочитав. Повторіть, коли він виправить причину.                                                                                                                                                                                                                                                              |
| `cancelled`  | `RuntimeError`    | Встановлення скасували                                                                                            | **Зупиніться**, не сприймаючи це як помилку. Див. зауваження нижче.                                                                                                                                                                                                                                                                                                      |
| `other`      | `RuntimeError`    | Усе, що рантайм не класифікує, наприклад циклічне посилання у змінній або запуск за маніфестом без блока `launch` | **Запишіть у лог і скажіть гравцеві.** Не повторюйте автоматично. Повтор навряд чи змінить результат.                                                                                                                                                                                                                                                                    |

::: tip Яка дія
«Повторити» означає той самий запит знову, можливо після очікування. «Зібрати заново» означає, що сам маніфест застарів або неправильний, тому повтор того самого бандла не може вдатися. Лаунчер, який лише повторює, зациклиться на випадку для перезбирання, тому вирішіть, що з двох застосовується, перш ніж щось планувати.
:::

### Зауваження до таблиці {#notes-on-the-table}

- **Поле `io` не має полів.** Звіт рантайма несе шлях, на якому сталася помилка, але `@opys/runtime` його не передає, тому шлях є лише в повідомленні. Покажіть повідомлення як є і не намагайтеся витягти з нього шлях.
- **Код `cancelled` сьогодні не може статися через `@opys/runtime`.** Рантайм може отримати токен скасування, але параметри, які приймають `install`, `prepare` і `launch`, його не включають, тому ці функції ніколи не дають цей код. Його перелічено, щоб лаунчер міг його обробити, коли скасування додадуть.
- **Код `other` покриває циклічне посилання у змінній.** Змінна, значення якої посилається назад на себе через інші змінні, надходить як `other`. Виправлення в маніфесті, тому зберіть його заново. Функції `prepare`, `buildLaunch` і `launch` також повідомляють `other` для маніфеста без блока `launch`, а `prepare` і `launch` роблять це до будь-якого встановлення.

## Помилки, які не є RuntimeError {#errors-that-are-not-runtimeerror}

Не кожне відхилення це `RuntimeError`. Два випадки надходять як звичайні помилки:

- **Погані аргументи** відхиляють до роботи рантайма, наприклад джерело, яке не є ні бандлом, ні URL, ні маніфестом, або параметр неправильного типу. Вони надходять як звичайний `Error`, який кидає біндинг. Його властивість `code` тримає код біндинга, наприклад `InvalidArg`, а не один із кодів вище, тому перевіряйте `instanceof RuntimeError`, а не сам `code`.
- **Програма, яку не можна запустити**, не є помилкою встановлення. Функція `launch` породжує процес після завершення встановлення, і Node повідомляє про програму, яку не можна виконати, наприклад про бінарник Java, якого немає, як про подію `error` на дитині, а не як про відхилення. Слухайте її, бо Node кидає подію `error`, яку ніщо не обробляє:

```js
child.on('error', (err) => {
  // помилка Node для spawn, наприклад ENOENT. Не RuntimeError.
});
```

## Обробка помилки {#handling-a-failure}

Цей приклад обробляє встановлення і пропускає без змін усе, що не є помилкою рантайма. Поля кожного підкласу він читає лише після перевірки `instanceof`, і саме це робить читання полів безпечним.

```js
import {
  install,
  RuntimeError,
  NetworkError,
  IntegrityError,
  ExtractionError,
} from '@opys/runtime';

async function installOnce(source, options) {
  try {
    await install(source, options);
    return { ok: true };
  } catch (err) {
    if (!(err instanceof RuntimeError)) throw err; // не наша: кидаємо далі

    switch (err.code) {
      case 'network':
        if (err instanceof NetworkError) {
          if (err.status === 404 || err.status === 410) {
            return { ok: false, action: 'rebuild', url: err.url };
          }
        }
        return { ok: false, action: 'retry-later' };

      case 'integrity':
        if (err instanceof IntegrityError) {
          return { ok: false, action: 'retry-once', paths: err.paths };
        }
        return { ok: false, action: 'retry-once' };

      case 'extraction':
        if (err instanceof ExtractionError) {
          console.error(`${err.artifactPath}: ${err.cause.message}`);
        }
        // Пошкоджений архів це перезбирання. Якщо причина каже, що диск повний
        // або каталог недоступний для запису, це має виправити гравець.
        return { ok: false, action: 'rebuild' };

      case 'manifest':
        return { ok: false, action: 'rebuild' };

      case 'io':
        return { ok: false, action: 'tell-player', message: err.message };

      case 'cancelled':
        return { ok: false, action: 'stop' };

      default:
        // 'other' і будь-який код, доданий пізніше
        console.error(err);
        return { ok: false, action: 'tell-player', message: err.message };
    }
  }
}
```

Гілка `default` важлива. Код, якого ця сторінка не перелічує і який додали в пізнішому релізі, потрапляє в неї, а не сприймається як відомий випадок.

Під `launch` ті самі відхилення надходять із самого виклику, бо `launch` встановлює перед породженням. Обгорніть виклик так само.
