# Змінні

Ця сторінка описує імена, які маніфест використовує для шляхів і для гравця, синтаксис `${name}`, що підставляє їх на місце, і те, що ви передаєте під час запуску. Вона перелічує кожне ім’я, яке маніфест Minecraft залишає відкритим для вашого лаунчера, і кожне ім’я, яке він визначає сам.

Маніфест збирають один раз і віддають кожному гравцеві, тому він не може тримати шлях на вашому диску чи обліковий запис гравця. Замість цього він використовує ім’я, а значення постачає машина запуску. Про функції, які приймають ці значення, див. [Встановлення і запуск](/uk/launcher/embedding). Поділ між двома машинами пояснено в розділі [Основні поняття](/uk/guide/concepts#two-machines-and-what-belongs-to-each).

## Як працює `${name}` {#how-name-works}

Запис `${name}` у шляху артефакта, у команді запуску, в аргументі, у значенні середовища або в робочому каталозі замінюють значенням `name`, коли рантайм його використовує.

- Значення може посилатися на інші імена. Запис `version_dir` це `${root}/versions/${version_name}`, і обидва імені визначають першими.
- Значення надходять із двох місць. Власні змінні маніфеста це основа, для чинних платформи й ознак. Передані вами `vars` накладають поверх, тому перемагають ваші.
- Ім’я, якого ніщо не визначає, лишається як написано. Запис `${username}` без переданого імені гравця доходить до гри буквальним текстом `${username}`. Рантайм про це не повідомляє.
- Запис `\${` дає буквальне `${`.
- Цикл, у якому ім’я посилається назад на себе через інші імена, завершується з кодом `other`.
- Передані вами значення проходять ту саму підстановку, тому значення, що містить `${x}`, розгортається.

## Що передає лаунчер {#what-the-launcher-passes}

```js
import { launch } from '@opys/runtime';

await launch(
  { bundle },
  {
    vars: { root, username, uuid, token, java_bin },
  },
);
```

Кожне значення це рядок. Виклик `launch` застосовує свої `vars` і до встановлення, і до запуску. Коли ви викликаєте `install` і `buildLaunch` окремо, передайте ті самі `vars` в обидва. Команда `opys launch <bundle> --var key=value` передає ті самі значення з командного рядка, і `--var` має перевагу над власними змінними маніфеста так само.

Значення `root` варто передавати завжди, як абсолютний шлях. Якщо його пропустити, воно дорівнює `.`, відносному до робочого каталога лаунчера, тому гру встановили б туди, звідки запустили лаунчер.

## Залишені відкритими маніфестом Minecraft {#left-open-by-a-minecraft-manifest}

Ці імена використовує маніфест і не дає їм значення, або дає лише типове, яке лаунчер має замінити.

| Name       | Used for                                                         | Notes                                                                                                                  |
| ---------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `root`     | Базовий каталог. Кожен типовий шлях лежить під ним.              | Плагін `minecraft` визначає його як `.`. Передайте абсолютний шлях.                                                    |
| `username` | Ім’я гравця (`auth_player_name`).                                | Типового немає. Без нього гра отримує `${username}`.                                                                   |
| `uuid`     | Id гравця (`auth_uuid`).                                         | Типового немає.                                                                                                        |
| `token`    | Токен доступу (`auth_session`, `auth_access_token`).             | Типового немає. Значення `0` запускає гру в офлайн-режимі, як показує розділ [Перші кроки](/uk/guide/getting-started). |
| `java_bin` | Програма, яку виконує запуск. Звичайна команда це `${java_bin}`. | Її визначає плагін `java`. Маніфест без цього плагіна залишає її вам.                                                  |

`java_bin` це єдине з них, якого потребує сама команда запуску. Передайте шлях до виконуваного файла Java або включіть плагін [`java`](/uk/guide/java), щоб маніфест надав його.

## Визначені маніфестом {#defined-by-the-manifest}

Плагін `minecraft` визначає ці імена для кожної версії. Передача значення для будь-якого з них його перевизначає, але зазвичай жодне цього не потребує.

| Name                  | Value                                                                                | Meaning                                                                                                   |
| --------------------- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `launcher_name`       | `opys`                                                                               | Ім’я лаунчера, яке повідомляє гра.                                                                        |
| `launcher_version`    | Власна версія opys, як випущено.                                                     | Версія, яку повідомляє гра.                                                                               |
| `version_type`        | Поле `type` з JSON версії, наприклад `release`.                                      | Тип релізу версії Minecraft.                                                                              |
| `version_name`        | Id версії: `1.21.1` для ваніли, інакше власний id завантажувача.                     | Ім’я версії. Частина `version_dir`.                                                                       |
| `game_directory`      | `${root}/`                                                                           | Каталог гри, із кінцевим слешем. Тут живуть збереження, налаштування й моди.                              |
| `assets_root`         | `${root}/assets`                                                                     | Сховище ресурсів.                                                                                         |
| `game_assets`         | `${assets_root}`, `${assets_root}/virtual/<index>` або `${game_directory}/resources` | Каталог, з якого старі версії читають ресурси за іменем. Значення залежить від розкладки ресурсів версії. |
| `assets_index_name`   | Id індексу ресурсів.                                                                 | Індекс, який читає гра.                                                                                   |
| `version_dir`         | `${root}/versions/${version_name}`                                                   | Тримає клієнтський jar і нативи.                                                                          |
| `library_directory`   | `${root}/libraries`                                                                  | Де зберігаються всі бібліотеки.                                                                           |
| `natives_directory`   | `${version_dir}/natives`                                                             | Куди розпаковують нативні бібліотеки.                                                                     |
| `auth_player_name`    | `${username}`                                                                        | Ім’я гравця.                                                                                              |
| `auth_uuid`           | `${uuid}`                                                                            | Id гравця.                                                                                                |
| `auth_session`        | `${token}`                                                                           | Токен доступу.                                                                                            |
| `auth_access_token`   | `${token}`                                                                           | Токен доступу під другою назвою.                                                                          |
| `user_type`           | `mojang`                                                                             | Тип акаунта.                                                                                              |
| `user_properties`     | `{}`                                                                                 | Властивості акаунта. Порожні.                                                                             |
| `clientid`            | Порожнє.                                                                             | Id клієнта. Порожній.                                                                                     |
| `classpath_separator` | `;` у Windows, `:` у Linux і macOS.                                                  | Розділювач між елементами `classpath`.                                                                    |
| `classpath`           | Шляхи бібліотек і клієнтський jar для цієї операційної системи.                      | Значення `-cp`. Клієнтський jar іде останнім, після всіх бібліотек.                                       |

Плагін `java` визначає ще три і задає одну змінну середовища:

| Name               | Value                                                                                                                 | Meaning                                                                              |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `java_runtime_dir` | `${root}/runtimes`                                                                                                    | Куди встановлюють JDK. Перевизначте, щоб перенести їх.                               |
| `java_home`        | Каталог JDK. У macOS закінчується на `/Contents/Home`.                                                                | Домашній каталог Java.                                                               |
| `java_bin`         | Виконуваний файл java. У Windows це `javaw.exe`, якщо не увімкнено ознаку `java_console` (передайте її у `features`). | Програма, яку виконує запуск.                                                        |
| `JAVA_HOME`        | `${java_home}`                                                                                                        | Змінна середовища, задана, щоб інструменти, запущені під час запуску, знаходили JDK. |

Завантажувач не додає власних імен. Forge, NeoForge і Fabric визначають `classpath` знову, зі своїми бібліотеками попереду ванільних. Cleanroom і lwjgl3ify читають повний документ версії й визначають ті самі імена. Значення `version_name` це id того документа, наприклад `1.12.2-Cleanroom-0.6.13-alpha`, тому `version_dir` йде за ним.
Інші плагіни визначають імена для власних файлів, наприклад `dgpuj_dir` і `dgpuj_bin` з плагіна `dgpuj`. Їх визначає маніфест, і від лаунчера вони нічого не потребують.

## Імена, які можуть використовувати аргументи гри {#names-the-game-s-arguments-may-use}

Власний перелік аргументів версії може посилатися на імена, яких opys не визначає. JSON версій везуть `--width ${resolution_width} --height ${resolution_height}` за ознакою `has_custom_resolution` і `--demo` за ознакою `is_demo_user`. Імена `resolution_width` і `resolution_height` не мають значення, поки ви його не дасте, а ознака вимкнена, поки ви її не передасте. Щоб задати розмір вікна, потрібні обидва:

```js
await launch(
  { bundle },
  {
    features: ['has_custom_resolution'],
    vars: { root, resolution_width: '1280', resolution_height: '720' },
  },
);
```

З увімкненою ознакою і без переданого значення аргумент доходить до гри буквальним текстом `${resolution_width}`. З вимкненою ознакою аргумент пропускають.
