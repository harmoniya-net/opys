# Розкладки ресурсів

Ця сторінка призначена для тих, хто реалізує формат, і для авторів модпаків, які хочуть знати, чому маніфест кладе ресурси саме туди. Вона охоплює три місця, де Minecraft зберігав свої ресурси (звуки, мовні файли, значки), і те, яке з них читає певна версія.

## Три розкладки, які вибирає індекс {#three-layouts-chosen-by-the-index}

Версія називає індекс ресурсів, документ JSON зі списком кожного об’єкта ресурсів. Документ каже, як гра шукає файли. Ніщо інше у версії цього не вирішує. Два прапорці в документі вибирають старі розкладки; індекс без жодного з них використовує гешоване сховище. Якщо задано обидва, перемагає `map_to_resources`.

| Розкладка        | Версії           | Прапорець індексу        | Куди потрапляють файли                     | Що повідомляють грі                                                                                                                |
| ---------------- | ---------------- | ------------------------ | ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| Гешоване сховище | від 1.7.3        | немає                    | `${assets_root}/objects/<ab>/<hash>`       | `--assetsDir ${assets_root}` і `--assetIndex ${assets_index_name}`: каталог зі сховищем та індексом, а також ідентифікатор індексу |
| Віртуальна       | від 1.6 до 1.7.2 | `virtual: true`          | `${assets_root}/virtual/<index id>/<name>` | `--assetsDir ${game_assets}`, тобто `${assets_root}/virtual/<index id>`                                                            |
| Ресурси          | до 1.6           | `map_to_resources: true` | `${game_directory}/resources/<name>`       | `--assetsDir ${game_assets}`, тобто `${game_directory}/resources`; гра зазирає туди, навіть якщо її не просили                     |

`<ab>` є першими двома символами гешу, а `<name>` є іменем об’єкта в індексі, наприклад `sounds/step/grass1.ogg`. У плагіні `minecraft` змінна `${game_directory}` має значення `${root}/`. Ідентифікатори Mojang для двох старих індексів: `legacy` і `pre-1.6`; новіші мають такі ідентифікатори, як `1.7.4` або `17`.

Кожна версія визначає `game_assets`, навіть ті, які його ніколи не читають. Сучасні версії отримують там `${assets_root}`, тому змінна пасує кожній версії.

## Що ламається на чужій розкладці {#what-goes-wrong-on-the-wrong-layout}

Гра, якій дали гешоване сховище, не падає під час читання своїх ресурсів. Вона нічого не читає і працює далі: гра запускається й біжить без звуку. Старі ігри шукають файли за іменем, а в гешованих назвах вони знайти нічого не можуть.

## Один файл в одному місці, зафіксований у кожній розкладці {#one-place-per-file-pinned-in-every-layout}

Файл лежить в одному місці. Офіційний лаунчер тримає гешоване сховище й копіює з нього файли для старих розкладок. opys так не робить: гра на старій розкладці сховище ніколи не читає, тому її файли завантажуються просто під своїми іменами, і копія сховища поруч не зберігається. Два імені з однаковим вмістом є двома файлами, кожен завантажується окремо: індекс `legacy` перелічує 1120 імен для 596 окремих гешів.

Кожен об’єкт фіксується тим sha1, який його називає, в усіх трьох розкладках. URL завантаження теж той самий:
`https://resources.download.minecraft.net/<ab>/<hash>`. Шлях є лише назвою, і ніщо в рантаймі не вичитує геш зі шляху. Без фіксації обрізане завантаження збереглося б.

Документ індексу ресурсів той самий у кожній розкладці. Він потрапляє до
`${assets_root}/indexes/<index id>.json`, зафіксований власним sha1.

## У маніфесті {#in-a-manifest}

Кожен об’єкт стає одним артефактом. Його `path` є шляхом розкладки, у якому змінні залишено для машини запуску, а його `metadata` зберігає ім’я об’єкта, щоб ім’я не губилося, коли файл стає гешованим. Артефакт гешованого сховища, як його пише плагін `minecraft` для 1.21.1:

```json
{
  "path": "${assets_root}/objects/22/227ab99bf7c6cf0b2002e0f7957d0ff7e5cb0c96",
  "source": {
    "url": "https://resources.download.minecraft.net/22/227ab99bf7c6cf0b2002e0f7957d0ff7e5cb0c96"
  },
  "size": 7126,
  "integrity": { "sha1": "227ab99bf7c6cf0b2002e0f7957d0ff7e5cb0c96" },
  "metadata": { "name": "minecraft/sounds/step/grass1.ogg" }
}
```

Віртуальний об’єкт має ті самі `source` та `integrity` і інший
`path`: `${assets_root}/virtual/legacy/sounds/step/grass1.ogg`. Шлях об’єкта до 1.6 має вигляд `${game_directory}/resources/newsound/step/grass1.ogg`. Список артефактів упорядковано за іменем об’єкта, тому дві збірки тієї самої версії дають той самий список.

У гешованому сховищі шлях будується з гешу, тому два імені з тим самим гешем ділять шлях. Збирання залишає для них один артефакт, і вцілілий `metadata.name` є пізнішим іменем. Індекс 1.21.1 має 3911 імен і 3888 окремих гешів, звідки беруться 23 артефакти, про які збирання повідомляє як про зняті дублікати.

## Де дивитися в коді {#where-to-look-in-the-code}

| Що                                             | Де                                                                                             |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Три розкладки й прапорці, які їх вибирають     | `crates/opys-mojang/src/assets.rs` (`AssetLayout`, `AssetManifest::layout`)                    |
| Шлях артефакта для кожної розкладки            | `crates/opys-minecraft-vanilla/src/mappers/assets.rs` (`asset_directory`, `map_asset_objects`) |
| Змінні `game_assets`, `assets_root` та індексу | `crates/opys-minecraft-vanilla/src/vanilla.rs`                                                 |
| Тести, які фіксують кожну розкладку            | `crates/opys-minecraft-vanilla/tests/mappers.rs`                                               |
