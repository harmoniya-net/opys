# API

Ця сторінка є довідником: який пакет що експортує. Кожен розділ називає один опублікований пакет, показує його встановлення і перелічує його публічні експорти із зазначенням виду кожного. Щоб дізнатися, як користуватися пакетом, перейдіть за посиланням на початку його розділу. `@opys/minecraft` повторно експортує більшість інших пакетів, а його розділ пояснює, які саме. Команда `opys` не експортує нічого.

## Життєвий цикл {#lifecycle}

`opys build` і `opys launch` виконують ті самі кроки до моменту, де вони розходяться. Про маніфест і дві машини читайте в розділі [Основні поняття](/uk/guide/concepts).

### `opys build` {#opys-build}

1. Завантажте файл конфігурації і визначте його. Функційна форма отримує `{ mode }`.
2. Запустіть метод `build(ctx)` кожного плагіна паралельно. Кожен повертає `Contribution`.
3. Обчисліть `manifest.command`, `args`, `workdir` і `envs` на основі груп запуску плагінів.
4. Об’єднайте внески в один маніфест і таблицю блобів, які він називає. Усі попередження злиття потрапляють у журнал.
5. Якщо вказано вихідний файл, запишіть у нього бандл. Якщо ні, виведіть маніфест як JSON, у якому немає блобів.

### `opys launch` {#opys-launch}

1. Завантажте і визначте конфігурацію, як у кроках від 1 до 4 команди `opys build`. Маніфест збирається в пам’яті, бандл не записується. (`opys launch <bundle>` натомість бере бандл як є. Конфігурація не завантажується, тому кроки від 1 до 3 не виконуються, а значення під час запуску постачає `--var`.)
2. Застосуйте `runClient`: маніфест поверхнево об’єднується з тим, що повертає `runClient`, по одному полю за раз. Повернутий `vars` замінює `vars` маніфесту повністю, тому конфігурації копіюють у нього `manifest.vars` через спред.
3. Перевірте, що кожна змінна є рядком або списком умовних значень.
4. Встановіть маніфест за допомогою `install` з `@opys/runtime`. Його події прогресу це фази `resolve`, `download`, `verify`, `extract` і `sweep`, а `download` додатково повідомляє про кожен файл як `download:start`, `download:bytes` і `download:done`.
5. Запустіть гру за допомогою `launch` з `install: false`, успадковуючи stdio, і дочекайтеся її завершення.

## @opys/mojang-rules {#opys-mojang-rules}

Формат правил за стандартом Mojang: типи і дві фабрики. Він не має обчислювача і залежностей, тому контракт можуть називати обидва боки поділу на збирання і рантайм. [Сторінка плагіна](/uk/plugins/mojang-rules).

```sh
npm install @opys/mojang-rules
```

| Назва               | Вид     | Значення                                                                  |
| ------------------- | ------- | ------------------------------------------------------------------------- |
| `OsName`            | тип     | `linux`, `windows` або `osx`.                                             |
| `OsArch`            | тип     | `x86`, `x86_64`, `arm`, `aarch64` або `any`.                              |
| `OsOptions`         | тип     | Платформа, відносно якої обчислюється правило: `name`, `version`, `arch`. |
| `OsConstraint`      | тип     | Частина `os` правила. Кожне поле необов’язкове і незалежне.               |
| `FeatureConstraint` | тип     | Назва ознаки, зіставлена з булевим значенням, яке вона повинна мати.      |
| `RuleAction`        | тип     | `allow` або `disallow`.                                                   |
| `MojangRule`        | тип     | Одне правило: дія з необов’язковим обмеженням `os` або `features`.        |
| `MojangRuleset`     | тип     | Список `MojangRule`.                                                      |
| `emptyRuleset`      | функція | Порожній `MojangRuleset`.                                                 |
| `allowOsRuleset`    | функція | `MojangRuleset`, який дозволяє одну назву ОС.                             |

## @opys/minecraft {#opys-minecraft}

Метапакет. Він повторно експортує поверхні пакетів домену Minecraft, щоб конфігурація могла імпортувати з одного місця. Його експорти надходять з названих нижче пакетів без змін. [Сторінка плагіна](/uk/plugins/minecraft).

```sh
npm install -D @opys/minecraft
```

Він повторно експортує кожен експорт цих пакетів через `export *`:
[`@opys/minecraft-vanilla`](#opys-minecraft-vanilla),
[`@opys/forge`](#opys-forge), [`@opys/neoforge`](#opys-neoforge),
[`@opys/fabric`](#opys-fabric), [`@opys/cleanroom`](#opys-cleanroom),
[`@opys/lwjgl3ify`](#opys-lwjgl3ify),
[`@opys/authliberty`](#opys-authliberty),
[`@opys/curseforge`](#opys-curseforge), [`@opys/modrinth`](#opys-modrinth),
[`@opys/link`](#opys-link),
[`@opys/minecraft-serverlist`](#opys-minecraft-serverlist) і
[`@opys/java`](#opys-java).

`@opys/dgpuj` і `@opys/bifrost` повторно експортуються за іменами, а ім’я, яке мають два пакети, експортується один раз:

- **dgpuj.** `dgpuj`, `resolveDgpuj`, `DEFAULT_REPO` і типи `DgpujOptions`, `DgpujPlatform` і `DgpujTemplate` надходять з `@opys/dgpuj`. Його `DEFAULT_PLATFORMS` пропущено, бо `@opys/java` експортує ім’я з таким самим написанням. Якщо він вам потрібен, імпортуйте його з `@opys/dgpuj`.
- **bifrost.** `resolveBifrost` з `@opys/bifrost` повторно експортується двічі: як `resolveBifrost` і як `bifrost`. `bifrost` не є плагіном, це та сама функція під іменем поруч із фабриками плагінів.
- **LoaderSpec.** Він експортується один раз, з `@opys/modrinth`. `@opys/curseforge` також експортує `LoaderSpec`, і обидва є тим самим типом.

Нічого іншого з `@opys/dgpuj` або `@opys/bifrost` тут не експортується: ані `DgpujRelease`, `DgpujReleaseAsset`, `DEFAULT_PLATFORMS`, ані `DEFAULT_TTL_SECONDS`. `@opys/core`, `@opys/dev`, `@opys/runtime` і `@opys/mojang` не повторно експортуються взагалі. Імена, експортовані вручну, такі:

| Назва                                            | Вид       | Значення                       |
| ------------------------------------------------ | --------- | ------------------------------ |
| `dgpuj`                                          | функція   | Плагін dgpuj. З `@opys/dgpuj`. |
| `resolveDgpuj`                                   | функція   | З `@opys/dgpuj`.               |
| `DEFAULT_REPO`                                   | константа | З `@opys/dgpuj`.               |
| `DgpujOptions`, `DgpujPlatform`, `DgpujTemplate` | тип       | З `@opys/dgpuj`.               |
| `bifrost`                                        | функція   | Псевдонім `resolveBifrost`.    |
| `resolveBifrost`                                 | функція   | З `@opys/bifrost`.             |
| `BifrostOptions`, `BifrostAuth`                  | тип       | З `@opys/bifrost`.             |
| `LoaderSpec`                                     | тип       | З `@opys/modrinth`.            |
